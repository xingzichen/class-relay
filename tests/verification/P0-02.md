# P0-02 · 共享契约、幂等与测试夹具

状态：**已验收**；执行者：Codex；日期：2026-09-10。依据：数据模型/技术架构基线 0.6、[开发计划](../../docs/development-plan.md#p0-02)，对应 A05、A17 的公共规则部分，不代表整条业务场景验收。

## 实现与边界

统一 action/payload/requestId 请求、响应和固定错误码；显式状态枚举、状态迁移检查、版本检查；稳定复合 ID 与规范化请求摘要；用户/函数/请求隔离的幂等判定；整数分、UTC 与上海日期工具；Clock、Repository、微信发送器和模型网关端口。

夹具含两班、同名学生、双孩、同孩子三亲属、多角色和委托家长。每次创建返回独立数据；内存事务替身支持隔离副本、唯一创建、乐观版本与失败回滚。所有数据均为合成值，不包含真实 OpenID/姓名/凭证。

## 单元验证

`contracts.test.ts` 4 项、`domain.test.ts` 11 项通过；全工程 32 项通过。实现前测试因生产模块缺失失败，完成实现后通过；变更后重复运行结果一致。

- 同用户/函数/requestId 同摘要重放；不同摘要或 action 冲突；不同用户/函数不串结果；PROCESSING 不重复执行。
- 组合键分隔符不碰撞，空字段拒绝；摘要保留数组顺序/类型，拒绝循环、非有限数、稀疏数组及非 JSON 值。
- 精确整数分及负余额；拒绝隐式四舍五入、指数、超限金额与溢出。
- UTC 格式与真实日期有效性、上海午夜跨日；非法状态/终态变化/过期版本拒绝。
- 夹具重置、全部亲属关联可找到对应用户/学生；替身副本隔离、重复创建失败、版本冲突只一方成功、异常回滚。

示例请求与错误：

```json
{"action":"save","payload":{"amount":5000,"student":"student-a1"},"requestId":"req-1"}
```

```json
{"ok":false,"requestId":"req-1","error":{"code":"IDEMPOTENCY_CONFLICT","message":"请求编号已用于不同内容。"}}
```

仅第二次使用相同请求编号且内容不同才返回该错误；此处展示契约，不表示 save 业务接口已经部署。
