## 已实现

- [atomic-batch.ts](../../packages/cloudbase/src/atomic-batch.ts) 接受固定文档 ID 的创建或完整替换计划，先验证并快照全部 JSON 输入，再进入事务。调用者必须先完成服务端业务授权；适配层没有客户端入口。
- 创建要求版本 1 且当前文档不存在；替换要求当前版本匹配、可选状态匹配、新版本恰好加一。拒绝重复目标、保留身份字段和非 JSON 数据。
- 单次最多 10 次写入，对应至多 10 次读取和 10 次写入。**这是应用主动设置的预算，不是平台实测容量。** 超限在启动事务前拒绝。
- SDK 事务重试参数设为 2；每次回调重读版本和状态。事务只执行固定数据库操作，不接受调用者回调，不调用微信、模型或其他外部服务。
- 读取、写入结果携带 SDK 错误码时抛出原错误供 SDK 识别冲突；函数边界仍应使用 `toErrorResponse` 脱敏。缺失读结果或写入确认时失败，不能误判为空文档或成功。

## SDK 对照与验证

锁定 `@cloudbase/node-sdk@3.18.3`，其数据库依赖 `@cloudbase/database@1.4.3`。依据已安装包的 `src/transaction/index.ts` 与 `src/document.ts` 检查真实实现：事务 `doc.get()` 返回单个 `data` 对象或 null；`doc.set()` 接受文档本体，事务写入返回 `updated`/`upserted`。适配层要求创建返回目标 ID 的 upsert 确认，替换返回 updated=1；真实环境若形状不同应记录并修正，不能放宽为任意结果即成功。

[7 项行为测试](../unit/atomic-batch.test.ts) 先因模块缺失失败，再实现通过。覆盖唯一创建、版本与状态检查、冲突后重读防止覆盖终态、第二次写入失败后的整批回滚、批次和参数拒绝、输入快照、SDK 返回错误及缺失确认。额外类型断言验证适配接口与已安装 Node SDK 数据库类型兼容。内存替身的回滚/冲突行为是单元边界模拟，不能证明真实云数据库具备同样表现。
