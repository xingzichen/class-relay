# 费用收取、核对与班内公示

版本 0.3 · 2026-09-08。本模块属于小程序主方案的必需功能；当前仅为文档，未发生实际收费或交易。

## 1. 已确认范围

用户已明确：家委会代收请人打扫、布置等事项产生的费用；第一版在线下或通过微信转账实际收款，小程序登记核对并公示。公示面向班内家长，逐个孩子公开已缴/未缴状态及金额，并公开资金使用和剩余情况。

第一版不接小程序微信支付，不把个人收款码描述为平台支付接口。小程序只保存收款安排和账目，不执行转账、代扣、退款交易或资金托管。线上支付仅作为后续扩展。

## 2. 费用事项（FR-FIN-01）

费用事项可关联通知、活动或采集任务，但保持独立财务状态。字段包括：班级、标题、用途（打扫/布置等）、依据与说明、预算、参与/分摊规则、目标学生、每人金额或差异金额及原因、登记截止、代收负责人、收款方式说明、预计支出、结余处理方式、附件、状态和版本。

首版默认按学生生成分摊项，避免同一孩子的妈妈、爸爸各被收取一次；一人多个孩子则分别分摊。支持金额减免、不参与、金额调整，保存确认依据；不通过删除孩子记录抹掉原分摊。

收费事项状态为 `DRAFT → OPEN → RECONCILING → CLOSED → ARCHIVED`，取消另记 `CANCELLED`。取消事项不抹除已收款，有资金时先明确退款/结转处置并登记结果。

实际收费依据、参与安排和代收负责人由班级运营方填写，小程序发布或内部复核本身不代表学校批准。

## 3. 收取与核对（FR-FIN-02）

1. 经办人建立费用事项和分摊明细，复核后发布收款说明，通知目标学生已关联亲属。
2. 家长在线下或微信转账完成付款，可在小程序对具体孩子/事项点击“提交缴费凭证”，填写金额、时间、方式、备注并上传必要凭证；家委会也可代登记。
3. 此时状态为“待核对”，不增加已核实实收，不标记已缴完成。
4. 家委会根据真实收款账户流水核对，录入到账日期、金额、渠道、交易参考信息及对应孩子/事项分配。
5. 另一位有财务复核权限的管理者确认后入账，更新孩子缴费状态和公示版本。系统管理员也不能复核自己经办的记录。
6. 对不符、重复、无法识别的付款标记待补充/驳回，说明原因，不凭截图自动认定到账。

同一笔付款可分配到多个孩子/事项，所有分配总和不得超过实际核实到账额；剩余部分列“已收待分配”，不能消失或重复分配。重复的真实交易参考号和凭证摘要提示冲突，由复核者判断；数据库以内部收款记录 ID 和入账幂等键保证同一记录不重复入账，不能仅用金额＋日期判断两笔交易相同。

## 4. 学生缴费状态（FR-FIN-03）

每个孩子的分摊行分别显示：应缴、累计核实实收、已退、净缴、待核对申报、未缴差额及状态。金额调整保留前后版本。

| 状态/标签 | 计算依据 |
|---|---|
| 未缴 | 应缴大于零，核实净缴为零 |
| 部分缴费 | 核实净缴大于零且小于调整后应缴 |
| 已缴 | 核实净缴等于调整后应缴 |
| 多缴待处理 | 核实净缴大于应缴，显示差额 |
| 无需缴费/不参与 | 明确登记的分摊调整状态，不等同于已收款 |
| 待核对 | 另有未确认申报，为叠加标签，不替代真实缴费状态 |
| 部分退款/已退款 | 显示退款事件及净缴；是否仍需缴费按调整后的应缴计算 |

退款不能自动推定免缴；如果是取消参与或降低分摊，需同步登记应缴调整。多缴不静默抵扣另一孩子或下一期费用，结转必须明确记账。

## 5. 支出、垫付与退款（FR-FIN-04）

支出记录包含所属费用事项、类别、用途、服务日期、金额、经办人、收款方必要信息、付款方式、凭证/票据、复核者、状态与实际付款时间。

- 预算与计划支出不减少余额。只有已实际付款且复核入账的支出计入现金支出。
- 家委会个人先行垫付的项目单列“待报销”，公开用途和金额；班费实际报销付款后才减少班费余额，避免垫付与报销双计支出。
- 退款关联原收款、孩子/事项和原因，保存实际退回凭证；申请退款不扣账面余额，实际退回并复核入账后扣减。
- 退款累计不得超过对应可退净收款；不通过改写原收款金额隐藏退费。
- 付款给清洁人员或布置供应方在小程序外完成；第一版由 CloudBase 云函数与云数据库登记和核对，不触发真实付款。
- 原始票据、转账截图单独受控保存；公示使用脱敏版本，隐藏账户号码、电话、交易标识和无关个人信息。

## 6. 余额与对账（FR-FIN-05）

金额统一使用人民币整数分，禁止二进制浮点累计金额。项目和班级总账分层计算：

```text
项目账面结余 = 项目期初结余 + 已分配核实收款 - 已分配核实退款
             - 已核实实付支出 + 转入 - 转出 + 已复核冲正净额
班级账面资金 = 班级期初资金 + 全部核实到账收款 - 全部核实退款
             - 全部核实实付支出 + 已复核冲正净额
核对差异 = 本次核实的班费专属实际资金 - 班级账面资金
```

“已收待分配”计入班级实收和班级账面资金，但尚不计入任何项目；分配动作只改变归属，不再次产生现金收入。内部项目结转成对记录，在班级总账净额为零。整体余额可与项目结余合计加未分配净额核对。

账面结余、待核对收款、待报销/计划支出分别展示；可另外显示预计可用余额，但不能与实际账面资金混称。不能把应收总额当成已收余额，也不能把家委会个人账户全部余额当成班费资金。

经办人定期上传/登记实际班费资金核对结果、核对日期、未达项和差异解释，复核者确认。存在差异时公示“有待核对差异”，保留最后一次核对时间；不得自动调整账本凑平。若发生真实超支，应如实显示负结余并说明垫付或待补来源，不截断为零。

示例：40 名学生各 50 元，核实收款 2,000 元；打扫实付 600 元、布置实付 300 元、实际退款 100 元，则项目账面结余为 1,000 元。退款对应孩子需展示退款记录及必要的应缴调整。

## 7. 公示页面（FR-FIN-06）

用户已确认按孩子在班内公开，不采用仅汇总公示作为第一版默认值。

| 页面内容 | 班内家长可见内容 |
|---|---|
| 项目总览 | 用途、范围、分摊规则、负责人、截止、版本、预算和依据说明 |
| 缴费明细 | 孩子姓名/必要的班内同名区分、应缴、核实实收、已退、净缴、缴费状态 |
| 资金使用 | 支出日期、用途、类别、金额、必要经办说明及脱敏凭证 |
| 剩余情况 | 期初、实收、退款、支出、结余、待分配、待报销、最后核对时间和差异 |
| 结项说明 | 结余退款/结转/继续保管方案及已实际执行金额 |
| 更正历史 | 修改原因、新旧版本、复核/公示时间，不能覆盖旧公示 |

公示不是公开互联网页面。仅正常入班且有关联在班孩子的普通家长、以及该班已授权管理身份可读；跨班用户、未审批访客和退出成员不可读。该权限是“班内费用公示”的专用可见范围，不因此开放其他家庭的私有任务、联系方式或原始付款凭证。

付款人的私人账户、具体家庭关系、转账流水标识不在逐孩子公示中展示。家长可查看自己孩子的完整业务缴费记录及自己提交的凭证；原始账务凭证仅相关经办/复核者与有权监督人员可见。

每次复核入账或分摊调整以云数据库小事务保存新修订与公示生成事件，云函数按修订异步生成不可变公示快照，保存统计口径和截止时点。审核发布且完整校验后才原子切换班内可见版本；生成期间显示上一完整版本和更新中提示，不能混用旧余额与新缴费列表。页面可说明通过原有渠道自行联系代收负责人，不设置账目疑问、争议受理或跟踪工单；家长不能直接改账。

## 8. 权限与协作（FR-FIN-07）

系统管理员、老师、家委会委员可在各自管理范围内维护费用事项和账目；具体经办人、复核人需要指定为不同账户，家委会成员承担代收登记工作。普通“管理员账户”不自动获得财务能力，必须单独授予 `finance.record`、`finance.review`、`finance.publish` 或 `finance.read_private`，且仍受班级范围和不得自复核约束。

| 动作 | 规则 |
|---|---|
| 建立费用事项、登记收款/支出/退款 | 三类管理身份或获授权经办者 |
| 入账复核与公示发布 | 有对应权限的另一位管理者；经办者不可自复核 |
| 已入账更正 | 新增冲正/更正申请，另一人复核，禁止直接覆盖/删除 |
| 修改代收负责人、收款说明 | 有权管理者修订并复核后公示，通知受影响家庭 |
| 原始凭证与导出 | 限有财务私有读取权限的范围；班内公示导出只含公开字段 |
| 查看公示 | 本班有效家长及管理身份，按第 7 节鉴权 |

系统管理员的最高层级不绕过账务不变式；无人复核时保留待复核，不自动入账。人员换届移交账本、凭证、余额核对和职责，旧授权失效，历史经办信息保留。

## 9. 追加式账本与通知（FR-FIN-08）

原始记录状态为 `DRAFT → SUBMITTED → VERIFIED_POSTED / REJECTED`。已入账金额不可原地修改，冲正引用原账目，新的正确账目另行复核。同一收款、退款、支出在状态迁移和账本写入间采用事务及唯一入账键。

单纯修改分摊规则不会改变已经发生的现金流水；撤销学生关联不会删除其历史缴费；项目取消或归档不会清空账本。

费用通知支持收款说明、公示更新、核对结果和结项，遵循订阅条件与限频。费用核对不得使用普通待办“点完成”作为到账证明。首版不默认对未缴学生自动持续催款；需要提醒时由管理者明确配置，目标仅有效相关亲属，未参与/免缴项不进入催办。公开已缴/未缴不生成羞辱性排名或自动群内点名。

## 10. 费用与 AI（FR-FIN-09）

AI 仅解释已发布公共用途、分摊规则及查看公示的步骤。逐孩子缴费状态、金额、班级余额等由确定性公示页面展示；AI 不检索个人缴费名单、不评价家庭、不判断争议、不推断欠缴原因。费用公示原有班内权限保持不变。

原始凭证、私人收款账户和待核对材料不进入 AI 知识库。AI 不入账、不复核、不处理反馈、不承诺代沟通或发起交易，统一遵守[AI 回复红线](ai-response-policy.md)。

## 11. 最小数据模型

以下实体映射为 CloudBase 文档型云数据库集合，凭证存云存储；唯一标识、引用约束与幂等采用服务端事务及确定性文档 ID 实现，不能假定存在关系型外键。

| 实体 | 主要字段与约束 |
|---|---|
| fee_projects | class_id, linked_task_id, purpose, basis, collector_id, status, version |
| fee_assessments | project_id, student_id, amount_fen, participation, adjustment_version；项目学生唯一 |
| payment_claims | applicant_id, student_id, project_id, declared_amount, proof_id, review_status；申报不入现金账 |
| cash_records | kind=RECEIPT/REFUND/EXPENSE, amount_fen, actual_at, operator_id, reviewer_id, status, proof_ids, external_reference |
| receipt_allocations | receipt_id, project_id, student_id, amount_fen；已分配总额不超过核实到账额 |
| refund_allocations | refund_id, original_receipt/allocation_id, amount_fen；限制可退余额 |
| expense_allocations | expense_id, project_id, amount_fen；垫付与实际报销分别记录 |
| ledger_entries | source_record_id, entry_kind, project_id可空, signed_amount_fen, reversal_of, posted_at；唯一入账键 |
| project_transfers | from_project, to_project, amount_fen, reason, reviewer；成对非现金归属变更 |
| reconciliations | class_id, cutoff, book_amount_fen, verified_actual_fen, difference_fen, explanation, reviewer_id |
| finance_publications | class_id, project_id, version, cutoff, totals, student_rows, redacted_evidence, publisher_id；不可变快照 |

期初资金通过独立复核的 OPENING 条目录入；冲正采用 REVERSAL 关联原条目。项目间分配和结转不能再次进入班级现金收入。核对记录保存其截止快照，不因之后新收款而更改历史差异。

## 12. 后续在线支付预留

用户已选择线下收款，因此第一版不以商户开通为交付前提。未来接入时增加商户/AppID、支付订单、验签回调、主动查单、退款与对账适配层，仍使用同一账本入账规则。接入要求见[微信支付官方准备说明](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)，不能在未验证前承诺资格或费率。
