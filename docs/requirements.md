# 微信群家委会智能维护系统产品需求文档

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 微信群家委会智能维护系统 |
| 文档版本 | 0.1 |
| 状态 | 需求基线 |
| 日期 | 2026-09-04 |
| 目标用户 | 班级家委会成员、系统管理员、班级家长 |

## 2. 背景

班级家委会承担家校沟通、活动支持、意见收集和协助处理公共事务等职责。具体工作通常不是长期连续项目，而是贯穿整个学年的低频持续职责，以及大量短期任务、周期任务和突发任务。

微信群是主要沟通入口，但存在以下问题：

- 老师通知分散在文字、图片、文件和引用消息中；
- 通知可能被修改、延期或取消；
- 家长容易错过原消息并重复询问；
- 家委会需要反复查找原文和解释公共信息；
- 活动组织涉及截止时间、志愿者、准备事项和待确认问题；
- 个案、收费、健康、成绩和争议问题需要严格控制回复边界；
- 现有个人微信没有面向普通群聊的稳定官方机器人接口。

本项目希望使用独立微信测试账号、本地模型和NAS知识库，减少家委会成员重复劳动，同时保留证据追溯、隐私控制和运行审计能力。

## 3. 产品目标

### 3.1 主要目标

1. 自动采集指定微信群中经过授权的老师消息。
2. 自动识别文字、截图和文件中的正式通知及关键字段。
3. 建立具有时间、版本和原始证据的班级知识库。
4. 在家委会群中识别家长公共问题并及时回答。
5. 由Agent直接决定发送、等待、忽略、创建任务或转私下处理。
6. 管理班级活动、周期任务、截止日期和待确认事项。
7. 对每次Agent决策和实际发送建立可审计记录。
8. 所有敏感数据和推理默认保留在本地网络。

### 3.2 成功定义

- 家委会成员查找和重复回复通知的时间显著下降；
- 自动回答均能追溯到有效老师通知；
- 通知变更后不再引用被替代的旧版本；
- 普通闲聊不会触发不必要的机器人回复；
- 个案和高风险问题被正确转入私下沟通或待确认状态；
- 系统重启、浏览器断线后不会重复发送已经成功发送的回复。

## 4. 非目标

本阶段不实现以下能力：

- 绕过微信扫码登录、安全验证、验证码或账号限制；
- 使用微信私有接口、协议逆向、客户端注入或内存Hook；
- 代替学校、老师作出政策解释、教育承诺或纪律决定；
- 处理学生成绩、病史、心理、家庭经济等个案事实；
- 以家委会名义收费、催缴、生成收款码或自动统计未付款学生；
- 代表全体家长自动形成意见或替代民主协商；
- 自动调解家长、学生、老师之间的争议；
- 保证微信网页版全年无人工重新登录；
- 把Agent会话记忆作为正式知识库。

## 5. 业务边界

### 5.1 家委会职责范围

系统围绕以下合理职责提供支持：

- 沟通学校和家庭；
- 向家长传达、解释可公开的学校与老师通知；
- 收集并整理家长的公共意见和疑问；
- 支持学校和班级活动；
- 协助安全、健康和家庭教育信息传播；
- 管理家委会内部的短期和周期任务；
- 对通知、反馈和执行情况进行追踪。

### 5.2 高风险边界

以下内容不得作为普通群自动问答处理：

- 具体学生身份、表现、成绩和排名；
- 健康、医疗、心理和特殊教育信息；
- 家庭住址、电话、证件、经济和困难情况；
- 家长或老师投诉、指责和争议事实；
- 收费、统一采购、教辅、捐赠和资金管理；
- 未经老师或学校正式发布的紧急处置建议；
- 需要学校行政决定或专业判断的问题。

Agent可直接决定使用 `DEFER`、`ESCALATE_PRIVATE` 或 `IGNORE`，但不得在群内扩散相关事实。

## 6. 用户与角色

| 角色 | 主要权限 |
|---|---|
| 系统管理员 | 配置群、身份、模型、Skills、知识库、保留策略；查看全部审计 |
| 家委会管理员 | 查看通知、任务、问题、Agent决策；纠正知识；暂停自动发送 |
| 老师 | 其经过绑定的群消息可成为权威事实；不是系统后台用户 |
| 家委会成员 | 在家委会群中提问、协作和接收自动回复 |
| 普通家长 | 在家委会群中查询公共信息；无后台访问权限 |
| 微信测试账号 | 浏览器登录身份；只在白名单群中采集或回复 |
| 家委会Agent | 读取授权数据、调用检索与任务工具、直接选择最终动作 |

## 7. 工作类型

### 7.1 持续性职责

- 监听权威通知；
- 维护通知当前版本；
- 回答公共问题；
- 收集未解决疑问；
- 维护群信息秩序；
- 保持审计和系统健康状态。

### 7.2 短期任务

- 运动会、春游、研学和开放日；
- 志愿者报名与分工；
- 材料、回执和物品准备；
- 活动时间、地点和变更通知；
- 活动后的信息归档。

### 7.3 周期任务

- 开学信息确认；
- 家长会和学校开放日；
- 安全、卫生和健康教育；
- 节假日与学期节点提醒；
- 学期意见收集和总结；
- 经验证后形成的活动模板。

### 7.4 突发任务

- 时间和地点临时变化；
- 活动延期或取消；
- 天气、安全和接送变化；
- 老师发布的高优先级通知。

## 8. 总体业务流程

### 8.1 老师通知流程

1. 浏览器插件捕获白名单群的新消息。
2. 系统验证群、发送者身份和消息幂等键。
3. 文字、图片或文件写入原始事件库。
4. Agent判断是否属于正式通知。
5. Agent提取事项、时间、地点、对象、行动和材料。
6. Agent检索可能被修改的历史通知。
7. Agent创建新知识，或创建修改、取消、延期版本。
8. 系统建立字段与原始证据关系。
9. 必要时自动创建任务或周期任务实例。

### 8.2 家长问题流程

1. 插件捕获家委会群消息。
2. 系统排除测试账号自己的发送消息。
3. Agent判断消息是公共问题、普通聊天、个案还是待确认事项。
4. Agent检索当前有效通知及其证据。
5. Agent直接选择最终动作。
6. `SEND` 类动作写入Outbox并由插件发送。
7. 插件回报发送成功或失败。
8. 系统保存问题、候选证据、Agent决定、工具调用和发送回执。

## 9. Agent最终动作

每个需要处理的家委会群消息必须选择零个或一个最终动作；普通消息可不触发Agent，触发后不得重复选择多个冲突动作。

| 动作 | 含义 |
|---|---|
| `SEND` | 直接回复有充分依据的公共问题 |
| `DEFER` | 信息不足，发送等待确认或暂未明确的说明 |
| `IGNORE` | 普通聊天、重复内容或无需回应 |
| `CREATE_TASK` | 从通知或讨论创建短期任务 |
| `UPDATE_TASK` | 更新任务进度、截止时间或状态 |
| `CREATE_CASE` | 记录家长意见、公共疑问或待确认事项 |
| `ESCALATE_PRIVATE` | 涉及个案或敏感信息，建议私下沟通 |
| `RELAY_URGENT_NOTICE` | 在授权群内转达老师发布的紧急通知 |

Agent拥有动作的语义决定权。宿主不得另行使用第二个模型推翻决定，但必须执行目标群白名单、工具参数Schema、幂等、限速和系统暂停开关。

## 10. 功能需求

### 10.1 微信与浏览器接入

#### FR-WX-001 群白名单

系统必须只处理管理员配置的群。

#### FR-WX-002 群权限模式

每个群必须配置为以下模式之一：

- `READ_ONLY`
- `READ_WRITE`
- `DISABLED`

学校家长群默认 `READ_ONLY`，家委会群默认 `READ_WRITE`。

#### FR-WX-003 消息采集

插件必须采集当前网页可见或通过白名单群导航可加载的文字、图片、文件、引用、撤回和群系统消息。

#### FR-WX-004 幂等

每条消息必须生成稳定的采集幂等键；重复加载网页不得产生重复业务事件。

#### FR-WX-005 自发消息排除

插件必须识别测试账号自己发送的消息，防止回复循环。

#### FR-WX-006 登录与健康状态

插件必须上报登录、断线、页面不可用、选择器失效和待重新扫码等状态。

#### FR-WX-007 不绕过验证

遇到扫码、验证码、安全校验或账号限制时，系统必须暂停发送并提示管理员处理。

### 10.2 身份与权威来源

#### FR-ID-001 身份绑定

管理员必须能把群成员绑定为老师、家委会成员、普通家长或测试账号。

#### FR-ID-002 名称历史

系统必须记录显示名称变化，显示名称不得作为唯一权威身份依据。

#### FR-ID-003 权威事实限制

只有绑定为老师或管理员明确授权的学校来源才能创建权威通知。

### 10.3 原始数据与附件

#### FR-RAW-001 不可变原始事件

原始消息不得被业务修改覆盖；更正、撤回和删除以新事件记录。

#### FR-RAW-002 内容寻址附件

附件必须按SHA-256去重并存入NAS内容寻址目录。

#### FR-RAW-003 图片理解

系统必须允许Qwen3.8读取图片并输出OCR文本、视觉描述、结构化通知字段及证据区域。

#### FR-RAW-004 文件解析

系统应优先使用确定性解析器提取PDF、Word和表格文本；解析失败时可将页面渲染为图片交给视觉模型。

### 10.4 知识库

#### FR-KB-001 结构化通知

通知至少包含标题、类别、发布者、发布时间、适用对象、事件时间、截止时间、地点、行动、材料、状态和置信说明。

#### FR-KB-002 通知版本

修改、延期、取消和恢复必须创建新版本，不能覆盖旧版本。

#### FR-KB-003 字段级证据

用于回答的每个事实字段必须能关联到原始消息、文件页或图片区域。

#### FR-KB-004 有效期

知识必须支持 `valid_from`、`valid_to` 和 `status`，检索默认排除已被替代和已取消版本。

#### FR-KB-005 混合检索

系统必须支持结构化过滤、中文全文检索、向量检索和重排。

#### FR-KB-006 模型版本

每条向量、OCR结果、结构化提取和决策必须记录模型与处理器版本。

### 10.5 自动问答与发送

#### FR-QA-001 问题识别

Agent必须区分明确提问、普通聊天、重复问题、个案问题、意见和任务讨论。

#### FR-QA-002 触发偏好

系统应优先响应以下消息：

- @测试账号；
- 引用测试账号回复；
- 明确出现“请问、想确认、老师是否说过”等查询表达；
- 与未完成任务直接相关的消息。

#### FR-QA-003 检索优先

Agent在调用 `SEND` 前必须调用知识检索工具，并为答案提供来源消息ID。

#### FR-QA-004 直接决定

Agent必须直接选择最终动作；宿主不进行二次语义审批。

#### FR-QA-005 发送工具

`SEND`、`DEFER`、`ESCALATE_PRIVATE` 和 `RELAY_URGENT_NOTICE` 必须通过统一Outbox工具执行。

#### FR-QA-006 循环防护

同一消息不得被重复回复；测试账号发送的内容不得再次作为家长问题触发。

#### FR-QA-007 来源表达

公共事实回复应尽量包含老师、发布时间或“根据最新通知”等可理解的来源提示。

### 10.6 任务与活动

#### FR-TASK-001 活动项目

系统必须支持活动、里程碑、任务、负责人、截止时间、依赖和状态。

#### FR-TASK-002 周期模板

系统必须支持从已验证流程创建周期任务模板，并按学期或日历规则生成实例。

#### FR-TASK-003 待确认状态

任务必须支持 `WAITING_TEACHER`、`WAITING_PARENTS` 等状态。

#### FR-TASK-004 任务来源

任务必须能关联到原始通知、家长问题或人工创建记录。

#### FR-TASK-005 提醒

Agent可直接决定在家委会群中发送任务提醒，但必须经过Outbox限速和幂等保护。

### 10.7 意见与个案分流

#### FR-CASE-001 公共意见

系统必须能创建、合并和跟踪公共意见或待确认问题。

#### FR-CASE-002 匿名摘要

系统应支持生成去身份化的意见摘要，但不得自动声称代表全体家长。

#### FR-CASE-003 个案分流

Agent识别到具体学生、健康、成绩、家庭、投诉或争议时，应使用 `ESCALATE_PRIVATE` 或 `IGNORE`。

#### FR-CASE-004 收费边界

系统不得实现收款、催款和未付款名单；费用问题必须引用学校正式通知或转人工确认。

### 10.8 管理与审计

#### FR-ADMIN-001 管理后台

管理员必须能查看群、身份、通知、版本、证据、任务、Case、Agent运行和Outbox。

#### FR-ADMIN-002 知识纠正

管理员必须能纠正提取结果；纠正必须产生新版本和审计记录。

#### FR-ADMIN-003 全局暂停

系统必须提供立即暂停自动发送的开关，不影响消息采集和知识入库。

#### FR-ADMIN-004 重放

管理员必须能使用历史消息重新运行指定版本的Agent和模型，但重放默认不得真实发送。

#### FR-ADMIN-005 决策审计

每个最终动作必须记录输入事件、检索结果、工具调用、模型版本、Skill版本、动作参数和发送回执。

## 11. 非功能需求

### 11.1 可靠性

- 原始消息入库和任务入队应具备事务一致性；
- Outbox采用至少一次投递、业务幂等实现实际至多一次发送；
- 服务重启后未完成事件可恢复；
- 浏览器断线期间知识处理可继续，发送任务保持待执行；
- 不承诺微信网页版未登录期间的消息完整性。

### 11.2 性能

初始目标：

- 文本消息入库P95不高于5秒；
- 普通公共问题从捕获到Outbox创建P95不高于30秒；
- 混合检索P95不高于2秒，不含模型生成；
- 后台页面常用查询P95不高于2秒；
- 图片解析允许异步完成，目标P95不高于60秒。

### 11.3 可扩展性

数据模型应支持：

- 多学校、多班级、多学期和多群；
- 百万级原始消息与检索单元；
- 附件容量独立扩展；
- 更换Embedding、Reranker、主模型和Agent Harness；
- 将全文或向量检索替换为独立服务。

### 11.4 安全与隐私

- 后端默认只在局域网开放；
- 浏览器插件只访问业务API，不直连数据库；
- 数据库不暴露公网；
- 模型调用默认不出本地网络；
- 采用最小权限、独立密钥和审计日志；
- 支持按数据类别配置保留和删除期限；
- 敏感Case解决后应尽快删除或匿名化；
- 未成年人信息不得用于系统目标之外的分析或画像。

### 11.5 可维护性

- 所有容器镜像、模型、Schema和Skills必须固定版本；
- 数据库变更必须通过migration；
- Agent与业务内核通过稳定的Typed API隔离；
- 关键流程必须支持历史事件回放测试；
- 不允许生产Skill运行时自我修改。

## 12. 数据保留建议

| 数据类型 | 默认策略 |
|---|---|
| 普通群聊天 | 当前学期或更短，处理后可清理 |
| 老师正式通知 | 当前学年保留，之后归档或按学校要求清理 |
| 通知版本和证据 | 与正式通知同期 |
| 已验证公共FAQ | 可跨学期保留，但新学期重新审核 |
| 个案与敏感信息 | 问题解决后尽快删除或匿名化 |
| 匿名任务模板 | 可长期保留 |
| Agent决策和发送回执 | 至少保留当前学年 |
| 附件 | 跟随其对应业务记录的最长保留期 |

最终期限应结合学校要求、群成员告知和实际必要性确认。

## 13. 验收标准

### 13.1 采集验收

- 白名单群文字、图片和文件事件能稳定入库；
- 重复打开群聊不会重复创建消息；
- 测试账号自己的消息不会触发回复循环；
- 网页结构失效时能够报警而不是静默漏采。

### 13.2 知识验收

- 同一通知的修改、延期和取消能形成正确版本链；
- 当前查询不会返回已被替代版本；
- 每个回答事实可以打开对应原文或图片证据；
- 图片通知能够提取至少时间、地点、行动和材料等核心字段。

### 13.3 Agent验收

- 每个处理事件最多产生一个最终动作；
- `SEND`必须包含有效来源ID；
- 费用、成绩、健康和个案问题不会得到群内事实性展开；
- 历史测试集不存在无来源事实被自动发送；
- 普通闲聊误回复率达到上线阈值后才开启自动发送。

### 13.4 可靠性验收

- 浏览器和后端重启不会重复发送已成功消息；
- 模型暂时离线时任务进入重试或待处理状态；
- 全局暂停能立即阻止新的真实发送；
- 数据库可从备份恢复，并能验证附件引用完整性。

## 14. 分阶段交付

### 阶段A：技术验证

- 验证测试账号能否登录微信网页版；
- 验证两个目标群的DOM结构和后台未读加载；
- 验证发送回执和稳定幂等键；
- 验证6-bit模型图片输入和工具调用。

### 阶段B：只读与影子运行

- 实现采集、知识库和检索；
- Agent产生动作但Outbox不真实发送；
- 使用真实历史问题评估误答、漏答和误触发。

### 阶段C：受限自动发送

- 只对@测试账号或引用测试账号的公共问题发送；
- 开放 `DEFER`、`IGNORE` 和有明确证据的 `SEND`；
- 保留全局暂停和实时审计。

### 阶段D：完整业务能力

- 开放任务、周期提醒、Case和紧急通知；
- 建立学期模板和管理看板；
- 根据运行数据调整触发与保留策略。

## 15. 待确认事项

1. 群晖型号、CPU架构、内存和存储卷类型。
2. Qwen模型主机的GPU或统一内存配置。
3. 目标微信账号是否稳定支持网页版登录。
4. 网页DOM能否获得足够稳定的群成员标识。
5. 学校和群管理员是否同意测试账号及数据处理方式。
6. 自动回复是否要求必须@账号，还是允许Agent判断所有群消息。
7. 原始普通聊天的实际保留期限。
8. 学校所在地关于家委会、群管理和收费的补充规定。
