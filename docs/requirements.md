# 产品需求：家校信息协同小程序

版本 0.2 · 2026-09-08。本文是待实现的需求基线；补充规则均为暂定默认值，汇总见[决策记录](decisions.md)。

## 1. 目标与范围

以班级学生为信息分发中心，建立“发布 → 提醒 → 查看/处理 → 回执 → 管理跟进”的流程。首期面向一个班试用，数据结构保留多班级、多孩子和多亲属能力。

本方案使用小程序内主动发布的信息，不依赖微信群监听。当前交付只包含方案文档；成绩排名、群聊机器人和自动抓取腾讯文档不在本期范围。费用登记与公示已加入必需范围；用户已选择线下/微信转账收款，第一版不接小程序内支付。

## 2. 身份与加入（FR-ID）

- **FR-ID-01**：首次加入必须选择至少一个身份，允许同时选择系统管理员、老师、家委会委员、普通家长中的多个；申请角色与已生效角色分别显示。
- **FR-ID-02**：默认流程为微信登录 → 班级邀请/入班申请 → 多选身份 → 提交申请 → 权限审核 → 可选关联孩子。未关联孩子的老师、家委会委员可以正常管理已授权班级。
- **FR-ID-03**：成员可以被设置为管理员账户；三类管理身份授权生效后默认拥有相应管理权限。普通家长被设为管理员不等于变为系统管理员，必须记录授权范围，详见[权限规范](permissions.md)。
- **FR-ID-04**：角色优先级为系统管理员 > 老师 > 家委会委员 > 普通家长。多角色按所在范围合并权限；界面切换“家长视角”不改变服务端权限。
- **FR-ID-05**：高权限角色不因用户自行勾选而生效。首位系统管理员由部署初始化绑定；后续管理身份由有权人员审批或直接授予。
- **FR-ID-06**：账户支持待加入、正常、停用、退出；角色和管理员授权可撤销。至少保留一位有效系统管理员，变更留审计。

## 3. 学生与亲属（FR-ST / FR-LINK）

### 3.1 班级学生名单

- **FR-ST-01**：系统管理员、所属班级老师和家委会委员共同新增、修改、归档学生名单；批量导入属于后续便利功能，不阻碍首版单个维护。
- **FR-ST-02**：学生至少包含稳定 ID、姓名、所属班级/在班状态、性别（男/女/未填写），可设置班内学号用于同名区分；不以姓名作为唯一标识。
- **FR-ST-03**：性别未填写的学生包含在“全体”，不自动进入男生/女生筛选，发布预览提示未填写人数。转班、毕业、离班采用在班关系归档，保留任务历史。
- **FR-ST-04**：多人同时编辑检测版本冲突；不静默覆盖他人修改。管理行为记录操作者、时间、变更前后版本。

### 3.2 关联孩子

- **FR-LINK-01**：老师、家委会委员、普通家长可选关联零到多个孩子；一个孩子可关联多个亲属账户。系统管理员需要亲属视角时可同时选择普通家长身份。
- **FR-LINK-02**：每个“账户—孩子”关联填写亲属身份：妈妈、爸爸、奶奶、爷爷、外婆、外公、其他（补充说明）。亲属称谓不提升管理权限，也不自动认定法律监护关系。
- **FR-LINK-03**：关联必须经该班家委会委员、老师或系统管理员审批后生效。申请人即使有管理身份，也不能审批自己的关联；只有一位管理员时由另一位合格管理者处理，不自动放行。
- **FR-LINK-04**：申请状态、审批人、审批意见、时间可追踪；拒绝后可以修改并重新申请；取消申请、撤销关联均留记录。
- **FR-LINK-05**：避免向待审批家长公开全班学生和亲属名单。默认使用班级邀请加孩子关联码，或姓名/班内标识提交申请，由审批者核对到学生 ID；不根据姓名自动绑定。
- **FR-LINK-06**：仅有效关联可接收孩子的任务和查看对应内容。撤销后停止新增提醒和访问；历史已发微信卡片不能收回，点击后重新鉴权。
- **FR-LINK-07**：多个亲属都可获知同一学生事项；普通任务和亲属信息限于自己有权关联的孩子，不开放其他家庭私有内容。费用章节明确要求的班内逐学生缴费公示是单独的公开范围。

## 4. 范围与群组（FR-AUD）

- **FR-AUD-01**：通知、采集、待办共用范围选择器，支持全体、女生、男生、个人多选、自建群组。“个人多选”暂按学生多选解释，待用户确认。
- **FR-AUD-02**：群组暂按班内学生集合设计，例如“合唱队”“春游志愿学生”。三类管理身份共同建立和维护；同一学生可进入多个群组。
- **FR-AUD-03**：多个范围取并集，学生去重；发布前显示最终学生数、有效亲属数、无关联亲属的学生数、预计可发送微信提醒人数。空范围阻止发布。
- **FR-AUD-04**：默认发布时冻结目标学生快照；之后群组或性别变化不追溯修改已发布范围。增减对象需要明确操作并生成修订记录；移出对象停止访问及后续提醒，历史记录保留。
- **FR-AUD-05**：亲属接收关系在创建接收记录时及每次发送前核对有效性。新审批亲属可看到目标孩子当前仍开放的事项并参与后续提醒，不补发全部过期事项。
- **FR-AUD-06**：没有关联亲属的学生仍保留任务实例，管理端显示“无有效接收人”，不能把这种情况计作已通知或已完成。

## 5. 通用任务（FR-TASK）

三类管理身份均可创建和发布所在范围内的通知、信息采集、待办事项。三种类型统一使用任务 ID、版本、范围、发布者、时间和状态，展示与完成逻辑按类型区分。

公共字段：标题、正文、类型、附件、班级、目标范围、截止时间（通知可不填，采集和待办必填）、提醒策略、可见范围、来源/关联任务、创建人与发布人。

- **FR-TASK-01**：支持草稿、发布、修订、取消、截止、归档。已发布内容创建新版本；标题、正文、范围、截止和执行要求的变化均留历史。
- **FR-TASK-02**：系统管理员可管理全部任务；老师可管理本班任务；家委会委员可共同管理本班家委会层级任务，不能直接修改老师/系统管理员发布内容，可提交修订建议。
- **FR-TASK-03**：发布前显示目标预览和提醒计划；重复点击提交不得产生两份任务。
- **FR-TASK-04**：任务修改默认保留已有完成回执；需要重新确认时，发布者显式选择“重新确认”，说明原因，生成新一轮完成记录。取消或归档后终止待发提醒。

### 5.1 通知（FR-NOTICE）

- **FR-NOTICE-01**：发布后对目标学生的有效亲属建立站内消息，并在具备订阅条件时发送服务通知。
- **FR-NOTICE-02**：分别记录提醒接口成功、打开详情、确认收到，不能互相替代。普通通知默认不要求完成；可勾选“需要确认收到”。
- **FR-NOTICE-03**：需要截止前反复催办的通知可关联一个待办，复用待办提醒规则。关联任务发布时合并同一业务事件的初始提醒，避免一次发布连发两条。

### 5.2 信息采集（FR-COLLECT）

- **FR-COLLECT-01**：创建采集说明、截止时间、目标范围，可关联跳转外部腾讯文档/收集表，发布产生通知。用户所称“腾讯云文档”暂按腾讯文档理解，具体产品和链接待验证。
- **FR-COLLECT-02**：页面显示“前往填写”和完成状态；打开链接只记作打开，不记作提交成功。
- **FR-COLLECT-03**：默认由亲属返回小程序点击“我已填写”，记录“亲属自报完成”；管理员可人工核验或退回。若配置必须核验，另显示“待核验/已核验”，自报后暂停催亲属，退回后恢复。
- **FR-COLLECT-04**：自动同步提交仅在验证目标文档 API、授权、回调/查询与身份映射之后实现；不能凭浏览器返回、页面停留时间或姓名推断提交。
- **FR-COLLECT-05**：采集可使用持续提醒策略或关联待办，同一目的仅保留一个催办源。外部文档必须单独设置访问权限，小程序权限不会自动传递到腾讯文档。

### 5.3 待办（FR-TODO）

- **FR-TODO-01**：支持独立待办或关联通知/信息采集，例如“周五前确认参加”“带好运动服”。关联关系不允许循环，创建时限定在同班可见任务内。
- **FR-TODO-02**：关联任务默认仅提供上下文，独立待办需要亲属点击完成；若是采集的催办待办，则显式使用“共享完成状态”，采集自报/核验/退回驱动该待办，不要求重复点击。
- **FR-TODO-03**：默认按学生完成，任一有效关联亲属点击后，该孩子此轮完成并停止对其所有亲属催办；支持发布时改为“每位亲属分别完成”。这是暂定默认值，需产品确认。
- **FR-TODO-04**：按亲属分别完成时，对每个目标学生的每位有效亲属生成实例。同一人有两个目标孩子时分别处理；重复点击幂等。一个孩子的完成不能替另一个孩子完成。
- **FR-TODO-05**：在截止前按提醒计划持续提醒未完成人员；完成、对象移除、关联失效、任务取消后停止。截止后标记逾期并停止截止前催办；是否允许补交由任务设置决定，默认允许并标记逾期完成。
- **FR-TODO-06**：管理者可以退回完成或代登记，必须说明原因并标明操作者，不能伪装为亲属点击。

## 6. 消息与提醒（FR-MSG）

- **FR-MSG-01**：站内消息中心持久展示待办、未读通知、审批状态；微信订阅消息只承担外部提醒。订阅被拒绝不妨碍进入和处理站内事项。
- **FR-MSG-02**：持续提醒是业务需求，微信外发必须满足实际模板、用户订阅状态、次数及平台规则；未获得长期订阅能力时不能承诺无限重复推送。详细验证见[可行性分析](feasibility-analysis.md)。
- **FR-MSG-03**：暂定提醒默认值：发布时一次、每天 18:00 一次、截止前 24 小时及 2 小时各一次；同一接收人同任务同轮次每天最多两次外发，最小间隔两小时，22:00—08:00 免打扰。发布者可调低频率；提高上限仅系统管理员可配置且仍受平台限制。
- **FR-MSG-04**：时间点重合合并；免打扰内的提醒顺延到下一允许时点，若已过截止则跳过。已错过的提醒点不集中补发；系统恢复只计算下一次有效提醒。默认时区 Asia/Shanghai。
- **FR-MSG-05**：优先发送任务变更/取消提示，其次临近截止、普通周期提醒；均遵循订阅条件、限频和免打扰。普通未要求确认的通知只初发及必要修订提醒。
- **FR-MSG-06**：微信拒绝订阅/额度不足显示“无法微信提醒”，临时错误显示“待重试”，网络超时结果未知显示“结果待核对”；不伪造送达或已读。无平台查询能力时不自动重复不确定发送。
- **FR-MSG-07**：每次外发前重查任务版本、截止、完成、亲属关联、角色/班级可见性和订阅条件。已交给微信的卡片无法保证撤回，但详情必须显示最新状态。

## 7. 共同知识库与 AI（FR-KB / FR-AI）

- **FR-KB-01**：系统管理员、老师、家委会委员共同维护班级知识库，支持手写解释、通知关联和附件。编辑遵循任务同级协作与上级保护规则。
- **FR-KB-02**：每条知识保存标题、正文、类别、班级/学生可见范围、来源、作者/发布者、版本、状态、有效时间。草稿、发布、过期、撤销、替代分别处理。
- **FR-KB-03**：已发布任务可成为引用来源，但只能提供给有权看该任务的用户；不得将定向通知自动变成全班知识。家委会解释必须标明解释者，不冒充老师原文。
- **FR-KB-04**：重要冲突（时间/地点/要求不一致）进入待确认列表；不能因某人的管理层级更高就覆盖另一份事实。经正式修订的有效版本优先，无法判断则提示联系老师。
- **FR-AI-01**：家长在小程序提问，AI 用当前有效且该用户可访问的老师通知、学校活动、事项解释回答；每个事实答案展示可点击来源及版本/更新时间。
- **FR-AI-02**：提问默认围绕当前选中孩子；多孩子问题明确选择范围。所有检索及引用下载均做权限检查，不能将全班名册、其他孩子私有任务或亲属信息输入模型；费用模块明确向班内公开的逐学生缴费信息按其专用公示权限处理，不扩展到其他私有数据。
- **FR-AI-03**：没有来源、来源过期或互相冲突时说明尚不能确认，提供人工咨询入口。AI 不审批关系、不提升身份、不替亲属点完成、不自行发布正式任务或修改知识。
- **FR-AI-04**：任务修订、权限变化后同步失效旧索引和缓存；模型不可用时仍可查通知、查看知识原文和完成任务。模型及部署方式可替换，尚未选定。

## 8. 费用收取与公示（FR-FIN）

用户已确认：家委会在线下或微信转账收取打扫、布置等费用，小程序负责登记、核实到账和公示；在班内逐个孩子公开已缴/未缴状态及金额，并公开支出和结余。

必需能力包括费用事项与学生分摊、缴费凭证申报、实际收款复核、支出与垫付/报销、退款、账面余额、实际资金核对、班内公示及更正记录。家长声明已缴不能直接作为到账；原始凭证与公示脱敏版本分开。详见[费用规范 FR-FIN-01 至 FR-FIN-09](finance.md)。

费用状态独立于普通待办；金额用整数分，已入账记录通过冲正更正而非覆盖。任一亲属点“完成”不会自动将孩子改成已缴。

## 9. 页面结构

| 页面 | 主要内容 |
|---|---|
| 加入与申请 | 多选身份、选择/加入班级、授权状态、关联孩子与亲属关系 |
| 首页 | 班级/孩子切换、未完成事项、最新通知、问答入口 |
| 消息中心 | 未读、审批结果、无法微信提醒提示、历史事项 |
| 任务详情 | 正文/来源、截止时间、最新版本、跳转填写、确认/完成 |
| 我的家庭 | 已关联孩子、亲属称谓、待审批申请、撤销关联 |
| 管理工作台 | 名册、身份/关联审批、管理员授权、群组、发布任务、统计 |
| 知识库 | 分类检索、原文、维护、版本、冲突待确认 |
| 费用公示 | 逐孩子缴费状态/金额、用途、支出凭证、余额、结项与更正历史 |
| 财务工作台 | 分摊、申报、收款核对、支出/退款、复核、公示和对账 |
| 系统设置 | 系统管理员专属配置、模板、提醒上限、审计与运行状态 |

## 10. 非功能要求

- 服务端逐请求鉴权，班级范围贯穿数据库、文件、导出和 AI 检索；普通家长可访问自己有效关联范围及本班已发布公共内容；逐学生费用公示是明确的班内公共范围，私有原凭证不公开。
- 管理操作、审批、发布/修订、完成/退回均留审计；任务与消息出站队列在同一事务保存。
- NAS 重启不丢任务和回执；发送与完成并发要尽可能撤销尚未发送提醒，不承诺外部服务严格恰好一次。
- 不收集无关身份证、住址等信息；附件受鉴权保护，订阅卡片使用简短摘要，详细孩子信息在登录后查看。
- 默认仅把授权知识片段提供给模型；接外部模型前明确数据范围和服务安排，不将全库或家庭名册上传。
- 目标为小规模真实网络下常用 API P95 ≤ 2 秒，AI 首次完整答复 P95 ≤ 30 秒；仅为待测目标，不是当前承诺。
- 日常备份、恢复演练、数据保留和退出删除流程在真实班级上线前落实，见架构与实施计划。
