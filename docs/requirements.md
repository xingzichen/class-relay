# 产品需求：家校信息协同小程序

版本 0.6 · 2026-09-10。本文是待实现的需求基线；本轮评审建议已采纳；未由用户指定的技术参数仍为可调整默认，汇总见[决策记录](decisions.md)。

## 1. 目标与范围

以班级学生为信息分发中心，建立“发布 → 提醒 → 查看/处理 → 回执 → 管理跟进”的流程。首期面向一个班试用，数据结构保留多班级、多孩子和多亲属能力。应用后端全部使用腾讯云开发 CloudBase，技术基线见[架构文档](technical-architecture.md)。

本方案使用小程序内主动发布的信息，不依赖微信群监听。当前交付包含方案文档与本地交互原型；成绩排名、群聊机器人和自动抓取腾讯文档不在本期范围。费用登记与公示已加入必需范围；用户已选择线下/微信转账收款，第一版不接小程序内支付。

### 1.1 可复用场景与明确边界

- **FR-SCOPE-01**：支持通知、作业要求、准备清单、公共说明、原生/外部采集、活动及志愿代报名、待办、课程/值日、费用公示、负责人交接与公共资料维护；轻量物资按后续阶段实现，仍属已采纳范围。
- **FR-SCOPE-02**：不建立家长问题反馈、意见收集、投诉工单、冲突调解、个案处理或敏感话题工作流，不替老师/家委会受理、转达、追踪或承诺处理。
- **FR-SCOPE-03**：信息采集仅用于明确可复用事务（活动参加确认、物品准备等），不能转为开放式投诉/敏感个案收集。管理员维护内容版本和账务更正仍是正常管理操作。

## 2. 身份与加入（FR-ID）

- **FR-ID-01**：首次加入必须选择至少一个身份，允许同时选择系统管理员、老师、家委会委员、普通家长中的多个；申请角色与已生效角色分别显示。
- **FR-ID-02**：默认流程为微信登录 → 班级邀请/入班申请 → 多选身份 → 提交申请 → 权限审核 → 可选关联孩子。未关联孩子的老师、家委会委员可以正常管理已授权班级。有效系统管理员执行管理操作无需逐班入班；所有亲属回执仍需本人有效孩子关联。
- **FR-ID-03**：成员可以被设置为管理员账户；三类管理身份授权生效后默认拥有相应管理权限。普通家长被设为管理员不等于变为系统管理员，必须记录授权范围，详见[权限规范](permissions.md)。
- **FR-ID-04**：角色优先级为系统管理员 > 老师 > 家委会委员 > 普通家长。多角色按所在范围合并权限；界面切换“家长视角”不改变服务端权限。
- **FR-ID-05**：高权限角色不因用户自行勾选而生效。首位系统管理员由部署初始化绑定；后续管理身份由有权人员审批或直接授予。
- **FR-ID-06**：账户支持待加入、正常、停用、退出；角色和管理员授权可撤销。至少保留一位有效系统管理员，变更留审计。

## 3. 学生与亲属（FR-ST / FR-LINK）

### 3.1 班级学生名单

- **FR-ST-01**：系统管理员、所属班级老师和家委会委员共同新增、修改、归档学生名单；批量导入属于后续便利功能，不阻碍首版单个维护。
- **FR-ST-02**：学生至少包含稳定 ID、姓名、所属班级/在班状态、性别（男/女/未填写），可设置班内学号用于同名区分；不以姓名作为唯一标识。
- **FR-ST-03**：性别未填写的学生包含在“全体”，不自动进入男生/女生筛选，发布预览提示未填写人数。转班、毕业、离班采用在班关系归档，保留任务历史。
- **FR-ST-04**：多人同时编辑检测版本冲突；不静默覆盖他人修改。管理行为记录操作者、时间、变更前后版本。

### 3.2 关联孩子

- **FR-LINK-01**：老师、家委会委员、普通家长可选关联零到多个孩子；一个孩子可关联多个亲属账户。系统管理员需要亲属视角时可同时选择普通家长身份。
- **FR-LINK-02**：每个“账户—孩子”关联填写亲属身份：妈妈、爸爸、奶奶、爷爷、外婆、外公、其他（补充说明）。亲属称谓不提升管理权限，也不自动认定法律监护关系。
- **FR-LINK-03**：关联必须经该班家委会委员、老师或系统管理员审批后生效。申请人即使有管理身份，也不能审批自己的关联；只有一位管理员时由另一位合格管理者处理，不自动放行。
- **FR-LINK-04**：申请状态、审批人、审批意见、时间可追踪；拒绝后可以修改并重新申请；取消申请、撤销关联均留记录。
- **FR-LINK-05**：避免向待审批家长公开全班学生和亲属名单。默认使用班级邀请加孩子关联码，或姓名/班内标识提交申请，由审批者核对到学生 ID；不根据姓名自动绑定。
- **FR-LINK-06**：仅有效关联可接收和处理孩子的任务；CLASS_PUBLIC 公共阅读与 TARGET_PRIVATE 定向阅读按 FR-AUD-07 分别鉴权。撤销后停止新增提醒和访问；历史已发微信卡片不能收回，点击后重新鉴权。
- **FR-LINK-07**：多个亲属都可获知同一学生事项；定向私有任务、回执和亲属信息限于自己有权关联的孩子；班级公共原文按 FR-AUD-07 开放，不开放其他家庭私有内容。费用章节明确要求的班内逐学生缴费公示是单独的公开范围。

## 4. 范围与群组（FR-AUD）

- **FR-AUD-01**：通知、采集、待办共用范围选择器，支持全体、女生、男生、个人多选、自建群组。“个人多选”按学生多选；志愿岗位另按实际成人参与人报名，由有效关联家长代填或走腾讯文档，不要求实际志愿者注册或订阅。
- **FR-AUD-02**：学生群组按班内学生集合设计，例如“合唱队”。成人志愿岗位/群组单独维护参与人及代填人，不把学生群组当作成人队伍。三类管理身份共同建立和维护；同一学生可进入多个群组。
- **FR-AUD-03**：多个范围取并集，学生去重；发布前分别预览阅读范围、需处理的学生数、有效关联关系数、按用户去重的亲属数、无有效接收人学生数及应用家庭偏好后的微信候选人数；真实可发送状态须按订阅观测和实际发送结果展示，不能凭关联人数推定。空范围阻止发布。
- **FR-AUD-04**：默认发布时冻结目标学生快照；之后群组或性别变化不追溯修改已发布范围。增减对象需要明确操作并生成修订记录；移出对象停止承担回执及催办；TARGET_PRIVATE 原文访问失效，CLASS_PUBLIC 仍按公共阅读资格判断。独立变更告知仅显示该家庭的移出结果，历史记录保留。
- **FR-AUD-05**：亲属接收关系在创建接收记录时及每次发送前核对有效性。新审批亲属可看到目标孩子当前仍开放的事项并参与后续提醒，不补发全部过期事项。
- **FR-AUD-06**：没有关联亲属的学生仍保留任务实例，管理端显示“无有效接收人”，不能把这种情况计作已通知或已完成。

- **FR-AUD-07**：阅读范围、处理对象和提醒对象分别保存与预览。CLASS_PUBLIC 面向本班正常成员且关联在班孩子的家庭及有权管理者；TARGET_PRIVATE 仅当前目标家庭及有权管理者。移出不取消仍有资格的公共阅读，但停止处理与催办；最小变更告知独立授权。

## 5. 通用任务（FR-TASK）

三类管理身份均可创建和发布所在范围内的通知、信息采集、待办事项。三种类型统一使用任务 ID、版本、范围、发布者、时间和状态，展示与完成逻辑按类型区分。

公共字段：标题、正文、类型、附件、班级、阅读范围（CLASS_PUBLIC/TARGET_PRIVATE）、处理对象、提醒接收策略、事项/活动 ID、维护负责人、截止时间（通知可不填，采集和待办必填）、提醒策略、来源/关联任务、创建人与发布人。

- **FR-TASK-01**：支持草稿、发布、修订、取消、截止、归档。已发布内容创建新版本；标题、正文、范围、截止和执行要求的变化均留历史。
- **FR-TASK-02**：系统管理员可管理全部任务；老师可管理本班老师及以下层级任务；家委会委员可共同管理本班家委会层级任务，不能直接修改老师/系统管理员发布内容，可提交修订建议。
- **FR-TASK-03**：发布前显示目标预览和提醒计划；重复点击提交不得产生两份任务。
- **FR-TASK-04**：任务修改默认保留已有完成回执；需要重新确认时，发布者显式选择“重新确认”，说明原因，生成新一轮完成记录。取消或归档后终止待发催办；必要取消告知通过独立事件发送，不受“已完成/已取消则不催办”条件误拦。
- **FR-TASK-05**：提供通知/作业/准备事项/待办模板，保存可复用字段与清单；从模板生成独立任务，必须重新确认日期、班级和目标范围，不复制旧亲属信息或完成状态。

### 5.1 通知（FR-NOTICE）

- **FR-NOTICE-01**：发布后对目标学生的有效亲属建立站内消息；外发依家庭偏好、逐亲属确认或志愿代填职责选取接收人，再校验订阅、限频和免打扰。班级公共阅读资格不自动扩大外发范围。
- **FR-NOTICE-02**：分别记录提醒接口成功、打开详情、确认收到，不能互相替代。普通通知默认不要求完成；可勾选“需要确认收到”。
- **FR-NOTICE-03**：需要截止前反复催办的通知可关联一个待办，复用待办提醒规则。关联任务发布时合并同一业务事件的初始提醒，避免一次发布连发两条。

### 5.2 信息采集（FR-COLLECT）

- **FR-COLLECT-01**：创建采集说明、截止时间、目标范围，可选择原生单选、数量、选项确认，或关联跳转外部腾讯文档/收集表，发布产生通知。同一表单只使用一个有效采集来源；结构化结果与外部自报不混称已验证。用户所称“腾讯云文档”暂按腾讯文档理解，具体产品和链接待验证。
- **FR-COLLECT-02**：原生页面保存结构化答复；外部页面显示“前往填写/我已填写”，打开链接只记作打开，不记作提交成功。原生已提交与外部自报使用不同来源和状态。
- **FR-COLLECT-03**：外部采集默认由亲属返回小程序点击“我已填写”，记录“亲属自报完成”；管理员可人工核验或退回。若配置必须核验，另显示“待核验/已核验”，自报后暂停催亲属，退回后恢复。
- **FR-COLLECT-04**：自动同步提交仅在验证目标文档 API、授权、回调/查询与身份映射之后实现；不能凭浏览器返回、页面停留时间或姓名推断提交。
- **FR-COLLECT-05**：采集可使用持续提醒策略或关联待办，同一目的仅保留一个催办源。外部文档必须单独设置访问权限，小程序权限不会自动传递到腾讯文档。

- **FR-COLLECT-06**：原生事务采集支持参加/不参加、数量、选项确认，按学生独立保存、截止前可修改；管理员可标来源代登记。提交表单、参加意向、名额确认分开；不参加也算已答复，不作为未完成反复催办。正式授权另走 FR-CONSENT。

### 5.3 待办（FR-TODO）

- **FR-TODO-01**：支持独立待办或关联通知/信息采集，例如“周五前确认参加”“带好运动服”。关联关系不允许循环，创建时限定在同班可见任务内。
- **FR-TODO-02**：关联任务默认仅提供上下文，独立待办需要亲属点击完成；若是采集的催办待办，则显式使用“共享完成状态”（待核验时暂停催家长，管理端继续跟踪核验），原生提交或外部自报及其核验/退回驱动该待办，不要求重复点击。
- **FR-TODO-03**：默认按学生完成，任一有效关联亲属点击后，该孩子此轮完成并停止对其所有亲属催办；支持发布时改为“每位亲属分别完成”。该默认值已采纳；仅用于普通事务确认，不代表监护人的正式授权。
- **FR-TODO-04**：按亲属分别完成时，对每个目标学生的每位有效亲属生成实例。同一人有两个目标孩子时分别处理；重复点击幂等。一个孩子的完成不能替另一个孩子完成。
- **FR-TODO-05**：在截止前按提醒计划持续提醒未完成人员；完成、对象移除、关联失效、任务取消后停止。截止后标记逾期并停止截止前催办；是否允许补交由任务设置决定，默认允许并标记逾期完成。
- **FR-TODO-06**：管理者可以退回完成或代登记，必须说明原因并标明操作者，不能伪装为亲属点击。

## 6. 消息与提醒（FR-MSG）

- **FR-MSG-01**：站内消息中心持久展示待办、未读通知、审批状态；微信订阅消息只承担外部提醒。订阅被拒绝不妨碍进入和处理站内事项。
- **FR-MSG-02**：持续提醒是业务需求，微信外发必须满足实际模板、用户订阅状态、次数及平台规则；未获得长期订阅能力时不能承诺无限重复推送。详细验证见[可行性分析](feasibility-analysis.md)。
- **FR-MSG-03**：默认发布时一次、每天 18:00、截止前 24/2 小时为候选提醒点；同人同任务同轮次普通外发每日最多两次，最小间隔两小时，22:00—08:00 免打扰。跨班、跨任务同一接收人每日外发总上限四次，其中普通发布/周期/催款合计最多两次，余下最多两次留给必要变更告知；未用额度不要求发满。管理员可调低，不提高这些硬上限。
- **FR-MSG-04**：重合提醒合并为摘要；免打扰顺延，过期催办跳过。错过时点不集中补发。变更告知使用独立告知有效期，不以原任务截止直接丢弃；默认只在变更影响仍有效时发送。时区 Asia/Shanghai。
- **FR-MSG-05**：事件分为 REMINDER（催办）、INITIAL（初发）、CHANGE_NOTICE（修订/移出/取消告知）。优先必要变更，其次临近截止、普通周期提醒；均遵循授权、额度、间隔与免打扰。取消事件不再承诺微信必达，管理端显示阻断及需人工关注列表。
- **FR-MSG-06**：拒绝订阅/额度不足显示“无法微信提醒”，临时错误“待重试”，超时未知“结果待核对”；无查询能力不盲重发。摘要每一项分别鉴权，不能泄露其他孩子内容。混合摘要按实际内容占各分类额度，外发总量只计一次；含催款必占催款子额度，不能改分类绕过上限。
- **FR-MSG-07**：每次外发按事件类型复核。任务催办检查当前任务开放、未完成、未过期及当前对象；催款改查当前费用、分摊/最新账本及待核对申报，志愿事项改查报名/邀请及有效代填关系，不伪造任务完成轮次；变更告知检查生效事件版本、原/新接收快照、当前账户/班级/有效亲属关系与最小内容权限，不因任务取消或亲属已完成而直接过滤。关系撤销/退班/停用仍阻断所有家庭外发；微信已交付卡片无法收回。
- **FR-MSG-08**：家庭可选择主要外部提醒接收人，默认仍为所有有效关联亲属；其他亲属站内事项保留。逐亲属确认向各自未完成者提醒；志愿报名向代填责任人提醒，未订阅或未注册的实际志愿者由代填人通过原有渠道联系，系统不虚构送达。
- **FR-MSG-09**：催款另受同一接收人跨所有费用事项每日最多两次的硬上限，手动和自动合并计数，不按孩子/项目/轮次重置，且占普通外发及全局总额度。固定包含“款项同步可能有延迟，如果已交款请忽略。”按最新复核账本判断，不按旧公示；自报已交只暂停该项催款、进入待核对，不增加实收。详见费用规范。

## 7. 共同知识库与 AI（FR-KB / FR-AI）

- **FR-KB-01**：系统管理员、老师、家委会委员共同维护班级知识库，支持手写解释、通知关联和附件。编辑遵循任务同级协作与上级保护规则。
- **FR-KB-02**：每条知识保存标题、正文、类别、班级/学生可见范围、来源、作者/发布者、版本、状态、有效时间。草稿、发布、过期、撤销、替代分别处理。
- **FR-KB-03**：已发布任务经管理者确认属于公共可复用事项并标记 ai_eligible 后，才可成为 AI 引用来源，且只能提供给有权看该任务的用户；不得将定向通知自动变成全班知识。家委会解释必须标明解释者，不冒充老师原文。
- **FR-RESOURCE-01**：知识库增设入学准备、家长会、阅读及学校确认的家庭教育资料分类；事项/活动 ID 及有效版本用于区分同事件变更和不同事件，AI 不将日期不同直接判为冲突。

- **FR-KB-04**：先按 topic_id/activity_id 和事实含义区分事项；同一事项有效来源的时间/地点/要求冲突时暂不用于确定性答案，两个不同活动时间不同不视作冲突，由管理者在原知识编辑功能中核验修订，不建立家长反馈或冲突处理工单；不能因某人的管理层级更高就覆盖另一份事实。经正式修订的有效版本优先，无法判断则提示联系老师。
- **FR-AI-01**：家长在小程序提问，AI 仅用当前有效、该用户可访问且标记适合公共可复用问答的老师通知、作业要求、学校活动、事项解释回答；每个事实答案展示可点击来源及版本/更新时间。
- **FR-AI-02**：提问默认围绕当前选中孩子；多孩子问题明确选择范围。所有检索及引用下载均做权限检查，不能将全班名册、其他孩子私有任务或亲属信息输入模型；费用公示、值日表按专用页面权限展示；AI 不检索个人缴费、个人值日名单或对家庭作评价。
- **FR-AI-03**：没有来源、来源过期或互相冲突时说明尚不能确认，提示用户通过原有渠道自行向相关人员核实，不创建咨询工单或自动代转达。AI 不审批关系、不提升身份、不替亲属点完成、不自行发布正式任务或修改知识。
- **FR-AI-04**：任务修订、权限变化后同步失效旧索引和缓存；模型不可用时仍可查通知、查看知识原文和完成任务。统一通过 CloudBase AI 调用腾讯混元，具体模型版本按已开通能力固定；不依赖本地推理服务。

- **FR-AI-05**：所有 AI 回复遵守[回复规范](ai-response-policy.md)，禁止指责、羞辱、隐私泄露、绝对承诺、冒充身份、未经依据的定性及虚构已反馈/已处理。
- **FR-AI-06**：越界问题仅给简短中性提示，不追问、长期保存敏感原文或自动通知他人；输出先校验来源和语气，不合格回退固定模板。

## 8. 费用收取与公示（FR-FIN）

用户已确认：家委会在线下或微信转账收取打扫、布置等费用，小程序负责登记、核实到账和公示；在班内逐个孩子公开已缴/未缴状态及金额，并公开支出和结余。

必需能力包括费用事项与学生分摊、缴费凭证申报、实际收款复核、支出与垫付/报销、退款、账面余额、实际资金核对、班内公示及更正记录。家长声明已缴不能直接作为到账；原始凭证与公示脱敏版本分开。详见[费用规范 FR-FIN-01 至 FR-FIN-11](finance.md)。

费用状态独立于普通待办；金额用整数分，已入账通过冲正更正。亲属普通完成不作为到账。自报已交仅暂停该孩子该事项催款；复核入账立即更新自家状态并停催，班内公示须完整快照审核后另行切换。催款每日两次、忽略提示及财务交接分别见 FR-FIN-10/11。

## 9. 课程表、值日表与临时调整（FR-SCH / FR-DUTY）

提供班级课程表、值日表的基础安排和按日期生效的临时调整，包括串课、代课、停课/补课、值日换人/换日期。调整仅影响指定范围，保留前后版本，并通知旧/新受影响学生的有效亲属。课程时间、值日日期、相应待办和提醒必须保持一致。完整规范见[课程与值日安排](schedules.md)。

## 11. 非功能要求

- 服务端逐请求鉴权，班级范围贯穿数据库、文件、导出和 AI 检索；普通家长可访问自己有效关联范围及本班已发布公共内容；逐学生费用公示是明确的班内公共范围，私有原凭证不公开。
- 管理操作、审批、发布/修订、完成/退回均留审计；任务正式发布版本与出站事件在同一小事务保存；目标实例与收件记录由云函数幂等分批展开，显示分发进度。
- 云函数超时、实例回收或重复触发不丢任务和回执；发送与完成并发尽可能撤销尚未发送的催办，必要变更告知按独立事件继续鉴权，不承诺外部服务严格恰好一次。
- 不收集无关身份证、住址等信息；附件受鉴权保护，订阅卡片使用简短摘要，详细孩子信息在登录后查看。
- 默认仅把授权知识片段提供给模型；通过 CloudBase AI 处理前明确数据范围和服务安排，不将全库或家庭名册上传。
- 目标为小规模真实网络下常用 API P95 ≤ 2 秒，AI 首次完整答复 P95 ≤ 30 秒；仅为待测目标，不是当前承诺。
- 日常备份、恢复演练、数据保留和退出删除流程在真实班级上线前落实，见架构与实施计划。

## 12. 活动统一入口（FR-ACT）

- **FR-ACT-01**：轻量活动统一关联报名、通知、准备待办、日程、志愿岗位、物资及费用。取消预览并统一失效待办/报名/未来安排，生成必要告知；已有资金进入核对处置，不自动退款。

活动业务状态不直接改写账本；取消涉及上级任务或财务处置时，须有权者核对整份关联清单后生效。完整工作流见[协作规范第 4 节](committee-workflows.md#4-活动统一入口)。

## 13. 成人志愿者与代填（FR-VOL）

- **FR-VOL-01**：实际志愿者与代填关联家长分开记录。实际参与人可无小程序账户/订阅；关联家长可替同一家庭成人填写，确认已征得参与人同意；系统只向有权且具备订阅条件的代填人发送。每个孩子应有至少一个有效关联家长作为运营准备目标；零关联仍保留异常提示，不伪造绑定。
- **FR-VOL-02**：支持岗位、时段、名额、退出、候补、替补确认及成人群组；以稳定参与人 ID 去重，不用姓名或账号单字段强行识别无账号成人。可整项改为腾讯文档采集，外部报名须人工核对后确认名额，不能把“我已填写”当成已占位。

参与人 participant_id 与代填人 submitter_user_id 分离。志愿报名采集模式由有 activity.manage 的管理者选择；如同时修改关联任务表单，还须具备该表单 task.manage 权限；普通家长不能自行切换整项活动的数据源。原生容量事务确认，外部自报待人工核验；不按姓名自动合并。双孩子关联不重复占同成人岗位，代填人失去关联后暂停向其外发并待重新指定。见[协作规范](committee-workflows.md)。

## 14. 负责人维护与交接（FR-HAND）

- **FR-HAND-01**：交接覆盖未完成/逾期事项、知识库、活动负责人、课程模板、财务材料、公示、未核对资金及旧授权；接收人确认、有权者生效，不能通过换届清空历史或提升内容层级。
- **FR-HAND-02**：支持按事项重新指派维护人、知识有效期维护和撤销旧管理授权；保留原作者、旧回执与账本。新旧经办及复核职责分离，未完成事项明列承接人和截止，不假装已经处理。

接收人只确认清单，不因此提权；有权者批准生效，当前维护人以 owner_id 表示，原作者与发布层级不变。升年级延续班级、转班、毕业及离班家庭资料分别处理。见[权限](permissions.md)与[交接流程](committee-workflows.md)。

## 15. 普通回执与正式授权（FR-CONSENT）

- **FR-CONSENT-01**：确认收到、准备完成、参加意向均是普通事务回执；正式监护人授权使用学校原有渠道，首版仅由具备 consent.record 的管理者记录线下核验状态、授权说明版本及核验人，不由任一亲属点击完成替代。缺少正式授权时不得显示已经取得。

核验状态为 PENDING / VERIFIED / REVOKED，均是学校原渠道的业务记录，不代表小程序签署；正式授权文本版本变化须重新核验，普通回执不能驱动其状态。

## 16. 轻量物资（FR-MATERIAL）

- **FR-MATERIAL-01**：物资清单记录数量、保管/认领人、领取/归还及关联采购支出，提供轻量分工，后续阶段实现，不增加完整库存系统。

认领不等于领取，归还不等于财务冲正。数量和保管变动追加事件，关联支出仍按费用复核规则；对应后续 P6 与 B16 验收。
