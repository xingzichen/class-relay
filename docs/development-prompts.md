# 开发提示词：逐任务执行

版本 1.2 · 2026-09-11 · 对应[开发计划](development-plan.md)的 **69 个开发包**，需求/设计基线 0.6。

## 使用方法

每次复制一个任务下方完整的 text 代码块交给开发助手即可，不需要另拼通用前缀。每段已经要求读取开发计划的统一测试标准、具体任务及业务依据，并明确前置依赖、实现、单元测试、阶段验证和交付证据。仓库提供上下文，执行助手应先核实当前实现，不能把文档里计划的代码当成已存在。

建议按编号顺序推进；不同执行顺序必须满足依赖。一个提示词只推进一个开发包：前置未完成时报告缺项并完成不依赖它的测试设计/契约，不用假实现掩盖缺项；外部资料缺失时先完成可离线部分，保留云验证待办。不要把一段包含所有提示词的长文本一次要求全部开发。

每个开发包必须同时有实现与单元测试，并按计划完成对应集成/真机验收。P0-01 已建立正式工程骨架与 `npm run check`；P0-01/P0-02 已验收，执行其提示词时先读现有代码及验证记录，不要重新覆盖工程。P0-03 的当前阻塞与恢复步骤见 [验证记录](../tests/verification/P0-03.md)。其他集成/AI/端到端命令在对应任务实现，不允许空脚本返回成功。

执行时遵守会话中已有授权；真实测试外发、付费资源、生产发布或真实数据使用若无授权，先完成可审核代码、脚本、测试与候选材料，明确剩余动作，不擅自执行。该限制不妨碍已授权的本地开发、修复和测试。
