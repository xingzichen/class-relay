### 2.2 正式开发所需软件

建议安装并固定以下工具：

1. Git，使用当前仓库工作；提交前确认没有 `.env*`、密钥或真实导出数据。
2. 本工程已固定 Node.js 22.22.1、npm 10.9.4 和 TypeScript 5.9.3，见 `.nvmrc`、`package-lock.json` 与 `config/toolchain.json`。开发云函数实际部署验证运行时为 `Nodejs22.21`，与本地主版本一致。
3. 最新稳定版微信开发者工具，用正式小程序 AppID 导入项目、打开云开发控制台和真机预览。
4. CloudBase CLI。按官方方式安装后登录：

   ```sh
   npm install -g @cloudbase/cli
   tcb login
   tcb --version
   ```

   日常团队开发更建议在正式工程有 `package.json` 后把 CLI 固定为开发依赖，通过 `npx tcb` 调用，避免成员间版本漂移。若 CLI 低于 2.12.0，部署配置可能覆盖线上全部函数环境变量；团队应固定并验证同一版本。
5. 编辑器及 TypeScript 支持。推荐开启保存时格式化、ESLint 和类型检查，但以正式工程提交的配置为准。

安装完成后留下本机基线记录：

```sh
git --version
node --version
npm --version
tcb --version
```

沿用已经建立的小程序、共享类型、云函数和测试目录，不另外生成脚手架。工具版本由仓库配置和锁文件固定，远端 CI 配置已建立但尚未实际在 GitHub 执行。

### 2.3 正式工程建议目录

P0-01 已建立以下工程结构；集合、索引与种子等数据库脚本仍属于 P0-04。

```text
miniprogram/             微信小程序与管理工作台
functions/               CloudBase 云函数，每个函数独立 package.json
packages/contracts/      请求、响应、状态与公共类型
```

开发与生产环境必须显式选择，客户端不得接受用户输入的任意环境 ID。建议在微信开发者工具的开发/体验版构建中固定开发环境，审核发布流水线固定生产环境。至少维护：

```text
MINIPROGRAM_APP_ID=<WECHAT_MINIPROGRAM_APP_ID>
CLOUDBASE_ENV_ID=<CLOUDBASE_ENV_ID_DEV_OR_PROD>
AI_MODEL_ID=<AI_MODEL_ID>
APP_STAGE=development|production
```

`MINIPROGRAM_APP_ID` 和环境 ID 通常不是密码，但仍应通过受控配置防止串环境；任何 API Key、令牌和真实模板配置不得写进小程序前端包。

### 2.4 本地联调顺序

1. 先打开原型，确认产品流程和术语。
2. 用微信开发者工具导入正式小程序工程，确认 AppID 正确。
3. 在开发版初始化 `wx.cloud.init({ env: <开发环境 ID> })`，只调用 `identity/bootstrapUser` 健康检查。
4. 云函数从 `getWXContext()` 读取 APPID/OPENID；前端传来的 openid、角色、`internal=true` 一律不能作为授权依据。
5. 先用模拟班级、模拟学生和测试微信号联调。真实姓名、账目、凭证和家庭关系只能在生产数据治理准备完成后进入生产环境。
6. 每完成一个模块，同时补单元测试、云端集成测试和权限反例；“控制台显示部署成功”不算业务验收通过。

## 3. 腾讯云上需要做什么

### 3.1 账号安全和费用责任

由腾讯云资产负责人执行：

- 主账号开启 MFA 和操作保护；日常开发使用 CAM 子账号。腾讯云官方也建议不要用主账号日常操作，而应按最小权限给子账号授权。
- 给开发、部署、只读审计分别建立独立身份或用户组；不要共享主账号、永久密钥或一个通用开发账号。
- 确认费用通知接收人、预算上限和欠费处理人。开通任何付费套餐、AI Token 包或安全增值能力前记录负责人和预算。
- 不要基于旧文档中的历史价格直接购买；以账号下单页显示的环境数量、区域、额度和超额计费为准。

参考：[腾讯云 CAM 用户与最小权限](https://cloud.tencent.com/document/product/598/13665)、[CloudBase 创建环境](https://docs.cloudbase.net/quick-start/create-env)。

### 3.2 创建并隔离 CloudBase 环境

推荐先在微信开发者工具中为正式小程序创建开发环境，因为该方式会自动关联当前小程序。环境初始化可能需要几分钟。

1. 微信开发者工具登录小程序管理员/开发者账号，打开项目并点击“云开发”。
2. 首次使用时同意条款、完成服务角色授权，创建开发环境，命名中明确 `dev`。
3. 记录完整 EnvId 和区域，不凭显示名称猜测。
4. 在 CloudBase 控制台的“环境配置 → 安全配置 → 小程序关联”核对正式 AppID。
5. 用开发工具和真机分别调用一个最小云函数，确认 `wx.cloud` 可以访问该 EnvId，并核对服务端取得的 APPID/OPENID。
6. P0 验证稳定后再创建独立生产环境，命名中明确 `prod`；选择环境数量和套餐时以当前账号控制台为准。

若环境先在腾讯云控制台创建，必须按官方步骤由主账号完成腾讯云账号与微信公众平台账号绑定，再核对该环境是否可用于目标小程序。不同环境的数据、存储、函数和配置相互隔离；数据库目前不能仅靠 CLI 自动完成跨环境复制，迁移必须有显式导出/导入或版本化初始化流程。

参考：[创建云开发环境](https://docs.cloudbase.net/quick-start/create-env)、[小程序调用 CloudBase 云函数](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。

### 3.3 数据库：先做 PoC，再由脚本建正式结构

P0 只创建少量测试集合，用来验证身份、事务、索引和拒绝直连。正式集合及字段以[数据模型](data-model.md)为准，应由可复查的初始化/迁移脚本创建，避免多人在控制台手工产生差异。

安全基线：

- `users`、权限、孩子关联、任务、回执、活动、财务、知识、问答、审计和消息队列等核心集合默认设为“仅管理端可读写”或等价的 `read: false, write: false`，全部经过云函数。
- 小程序端即使猜到集合名或文档 ID，也必须读写失败。不能因云函数已有鉴权就把数据库开放为“所有用户可读”。
- 开发/生产分别创建集合和索引，生产不导入测试家庭数据。
- 按[数据模型](data-model.md)中的查询和唯一键设计复合索引；发布前用真实查询路径验证，不能只看索引已创建。
- 财务账本、审计事件、回执事件采用追加记录和版本控制，不允许控制台直接覆盖作为日常操作方式。

参考：[数据库基础权限](https://docs.cloudbase.net/database/data-permission)、[数据库安全规则](https://docs.cloudbase.net/rule/introduce)。

### 3.4 云存储：默认私有

1. 建立至少 `attachments/`、`knowledge-source/`、`finance-private/`、`finance-public/`、`family-exports/` 的逻辑前缀和文件元数据约定。
2. 存储安全规则默认拒绝客户端直接读写；上传、受控下载和限时访问均由云函数校验业务权限。
3. 原始付款凭证绝不放到公开目录；财务公示使用单独生成的脱敏副本。
4. 用两个测试微信号验证：跨用户覆盖、目录枚举、猜 fileID、旧临时链接和撤权后访问均失败。
5. 数据库回档不等于附件历史恢复，另建云存储文件清单和归档方案。

参考：[云存储安全规则](https://docs.cloudbase.net/storage/security-rules)。官方说明安全规则主要约束客户端，控制台和服务端仍有完整权限，因此服务端业务鉴权不能省略。

### 3.5 云函数、权限和部署

初始 PoC 至少部署五类函数：

| 函数 | 验证目的 | 客户端是否可调用 |
|---|---|---|
| `identity` | 获取可信微信上下文、建立测试用户 | 是，仅已登录非匿名用户 |
| `p0Transaction` | 验证文档型数据库小事务、并发冲突和幂等 | 是，仅测试账号；P0 后删除或关闭 |
| `p0Storage` | 验证授权上传、受控下载和撤权 | 是，仅测试账号；P0 后删除或关闭 |
| `reminderScheduler` | 验证定时触发、租约、游标和重复执行 | 否，仅内部触发 |
| `qa` | 验证授权检索、混元调用、超时和固定回退 | 是，仅已登录非匿名用户 |

后续业务函数按[数据模型中的命令边界](data-model.md#4-云函数命令边界拟定)逐步加入，不应把所有权限集中到一个可由参数切换为“内部模式”的入口。

部署基线：

- `cloudbaserc.json` 明确 EnvId、函数目录、handler、`Nodejs20.19` 运行时、超时、内存、依赖安装和触发器；开发与生产使用独立配置或受控注入。
- 先部署单个函数并检查 diff，再批量部署；生产部署保留操作者、Git commit、目标 EnvId 和结果。
- 函数级安全规则必须有 `*` 默认项。业务入口只允许已登录、非匿名用户；内部函数显式 `false`。安全规则只控制“谁能调用函数”，函数内部仍须检查班级、角色、关联、版本和对象状态。
- 密钥只放函数环境变量或受控密钥设施。不要把环境变量写进客户端，也不要在日志打印环境、微信身份、问题全文、知识片段或凭证。

官方 CLI 示例：

```sh
tcb fn deploy <functionName> -e <CLOUDBASE_ENV_ID_DEV>
```

参考：[CloudBase CLI 快速开始](https://docs.cloudbase.net/cli-v1/functions/quick-start)、[部署云函数](https://docs.cloudbase.net/cli-v1/functions/deploy)、[云函数配置与运行时](https://docs.cloudbase.net/cli-v1/functions/configs)、[函数安全规则](https://docs.cloudbase.net/cloud-function/security-rules)、[函数环境变量](https://docs.cloudbase.net/cloud-function/function-configuration/env)。

### 3.6 定时触发器

给 `reminderScheduler` 配置一个 timer 触发器，开发环境先使用低频测试规则，确认控制台所用时区和 Cron 含义后再定生产频率。当前设计初值为每分钟检查到期任务，但必须先验证套餐、最小粒度、扫描成本和函数超时。

定时函数必须：分页、保存游标、使用数据库租约、允许重复触发、临近超时主动退出。微信发送结果未知时标记 `UNKNOWN`，不得盲目重发。生产启用前验证 22:00—08:00 免打扰、两小时间隔以及每用户跨班每日普通/变更/催款预算。

触发器可随函数配置版本化；官方当前说明每个云函数只支持一个触发器。参考：[云函数触发器配置](https://docs.cloudbase.net/cli-v1/functions/configs)。

### 3.7 CloudBase AI / 腾讯混元

1. 在开发环境进入 CloudBase AI+ 控制台，开启模型能力。
2. 从账号实际可用列表选择一个中文文本模型，记录准确模型 ID、套餐或 Token 计费、地域、日志/数据保留说明。
3. 云函数安装并固定兼容的 `@cloudbase/node-sdk`；只允许 `qa` 服务端调用，不从小程序前端直连模型。
4. 配置 `AI_MODEL_ID`、单问题输入上限、单用户/单班日调用与 Token 预算，以及一键暂停开关。
5. 仅把鉴权后、当前有效、标记 `ai_eligible` 的最小公共片段交给模型；个人账目、名册、报名名单、正式授权材料和私人凭证禁止进入模型。
6. 跑完[AI01—AI21](ai-response-policy.md#7-验收用例)及超时、限流、非 JSON、伪造来源和撤权用例后，才允许进入生产。

具体调用链见[腾讯云 AI 实施设计](ai-cloudbase-design.md)。参考：[接入大模型](https://docs.cloudbase.net/ai/model/model-access)、[CloudBase AI Node SDK](https://docs.cloudbase.net/ai/model/nodejs-access)。模型和套餐会变化，必须以目标环境控制台为准。

### 3.8 日志、监控和预算

为开发和生产分别完成：

- 查看每个云函数的调用次数、错误次数、运行时间、资源使用量和外网流量；对身份、财务、提醒和 AI 函数重点监控。
- 建立结构化错误码和随机 request ID，日志默认去标识化；严禁记录孩子姓名、原始问题全文、知识全文、OpenID、付款截图或模型完整响应。
- 设置错误率、连续失败、执行时长、资源/API 配额、存储容量和费用告警；明确短信/邮件/微信接收人。
- 业务侧另保存 `ai_usage_daily`、通知预算、作业积压和 UNKNOWN 发送结果等指标。平台资源监控不能替代业务告警。
- P0 压测一个模拟班级，估算云函数、数据库、存储、日志、订阅消息和 AI 用量，再决定生产套餐。

参考：[云函数监控](https://docs.cloudbase.net/cloud-function/debugging/monitor)、[CloudBase 价格](https://tcb.cloud.tencent.com/pricing)。价格只以购买当日账号页面为准。

### 3.9 备份、回档和恢复演练

1. 在“文档型数据库 → 数据库设置”核对目标套餐的自动备份、可回档时间点和保留期。
2. 在开发/隔离环境做一次回档演练。官方当前行为是回档生成新集合，不直接覆盖原集合。
3. 为云存储维护独立文件清单与归档；数据库回档不会自动补齐附件历史。
4. 恢复后先暂停外发和敏感管理操作，核对撤权/交接、报名容量、账本修订、公示版本、文件清单和当日发送预算，再切换读取。
5. 记录恢复负责人、步骤、耗时和证据。未演练的“有备份”不能作为上线保证。

官方当前说明数据库每日自动备份，默认保留 7 天，但实际可用范围仍以目标环境控制台为准。参考：[数据库回档](https://docs.cloudbase.net/database/backup)。

## 4. 不在腾讯云控制台、但上线必须完成的操作

### 微信公众平台 / 微信开发者工具

- 完成小程序主体、类目、备案、隐私保护指引、用户隐私授权和版本审核。
- 添加项目成员/体验成员，撤销离岗人员权限；不要共用管理员微信。
- 为真实业务申请订阅消息模板，记录模板 ID、字段和页面路径；真机测试用户同意、拒绝、模板失效、次数耗尽和发送失败。
- 订阅消息只是外部提醒，不保证持续、无限次或必达；站内 `inbox_items` 才是持久通知记录。
- 小程序代码包仍由微信开发者工具上传、体验、审核和发布，不能用 CloudBase 函数部署代替。

### 腾讯文档

- 先确定使用“腾讯文档”还是“收集表”、负责人、真实链接、访问范围和保留期。
- 在真机验证打开、登录、填写、返回和权限；打开页面不算提交。
- 首版按“家长自报 + 管理员人工核验”落地，不把尚未验证的自动回调/同步当成已具备能力。
- 若使用 `web-view`，另行核对小程序主体资格和业务域名要求；采用 CloudBase 不会自动取得外部网页访问资格。

这些外部依赖及回退方式见[可行性分析](feasibility-analysis.md#3-微信订阅消息)和[家委会协作流程](committee-workflows.md)。
