## 2. 当前设计默认值

| ID | 当前决定 | 理由 |
|---|---|---|
| D01 | 自选管理身份先申请后授权；初始化首位系统管理员 | 防止勾选即获得最高权限 |
| D02 | 管理能力与身份分离，委托不授予关联审批权 | 同时满足可设管理员和审批身份门槛 |
| D03 | 系统管理员全局，其他角色按班级授权 | 兼容跨班任职与多孩子 |
| D04 | 关联申请禁止本人审批 | 避免管理者自己证明自己的亲属关系 |
| D05 | 个人多选按学生解释，学生群组按班内学生集合；成人岗位见 U18 | 与通知关联亲属的目标模型一致 |
| D06 | 发布冻结学生范围，有效亲属动态更新 | 防止后改群组静默扩大通知范围，又能接纳新亲属 |
| D07 | 待办默认每个孩子任一亲属完成，可选每位亲属分别完成 | 避免同一家庭重复操作，保留逐人确认场景 |
| D08 | 候选时点为初发、每天 18:00、截止前 24/2 小时；同人同任务同轮次普通外发每日最多两次，并受 D17 总量、两小时间隔和 22:00—08:00 免打扰限制 | 将持续提醒转为可配置计划，仍受平台约束 |
| D09 | 采集可选原生简单表单或腾讯文档/收集表，每表一个当前来源；外部自报与核验分开，换源保留版本和历史 | 未确认具体产品及自动同步能力 |
| D10 | 同级共享编辑、下级不能直接改上级发布内容 | 同时表达共同维护与权限层级 |
| D11 | 截止后停止催办，默认允许逾期补交 | 将逾期与禁止提交分开 |
| D12 | CloudBase 文档型云数据库、云函数、云存储、定时触发器和 CloudBase AI 混元 | 在用户指定平台内形成统一实现；数据库模式和具体模型是实现选型 |
| D13 | 财务职责显式指派；经办与复核分离，公示另行审核发布；已入账记录用冲正修正 | 避免多人协作误记账，保持可追溯 |
| D14 | 课程由系统管理员/老师维护，家委会默认管值日；课程可显式委托 | 课程变更涉及教学安排，现按统一能力目录实施 |
| D15 | 周期基础表加指定日期覆盖；跨班串课整体校验，提醒按有效日程生成 | 保留基础安排，避免部分修改与旧提醒 |
| D16 | AI 首版采用受控 `qa` 云函数编排：先鉴权和检索，再调用混元并校验完整输出；不把全库或写操作工具交给通用 Agent | 满足班级权限、来源追溯和语气红线，模型失败仍可查原文 |
| D17 | 总量落实为同接收人跨班/任务每日四次，其中普通初发/周期/催款合计两次、其余两次留给必要变更；催款另有两次子上限，手动自动统一、间隔两小时、22:00—08:00 免打扰。数字四次与额度分配为本轮实施默认，不视为用户单独指定；可调低。 | 总量与分桶为设计默认；催款两次为用户明确上限 |
| D18 | 志愿报名以稳定参与人 ID + 岗位/时段去重，无账号者不以姓名自动合并；只向有效代填人提醒。每个活动表单选择原生或外部唯一有效采集源。 | 实际参与人和订阅接收人不同，防止重复名额 |
| D19 | 全局管理员管理操作免逐班入班；日程管理能力包含发布撤销；财务私有职责必须显式指派；交接不自行提升内容层级。 | 管理范围、业务职责和原文层级分别检查 |

用户已采纳评审建议；D 系列中的具体技术选型和默认数字是实施规则，可在保持用户约束的前提下版本化调整，不能把设计默认值误记为用户逐项指定。

## 4. 分支边界

备选分支保留原设计、全部旧图和当时未提交的监听器源码、测试及命令脚本。`.local/`、`.build/` 和凭据继续排除，未删除本地运行数据。主分支用新的需求、架构、权限、模型、费用和验收文档形成独立方案；此处仅记录方案保存边界；文档与本地原型交付不代表生产部署。
