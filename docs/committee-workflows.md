# 家委会协作、活动与交接

版本 0.6 · 2026-09-10。评审建议已采纳，志愿者代报名、每天最多两次催款及交接范围按用户本轮补充执行。本文为需求与设计，原型只模拟，不代表正式服务已上线。

## 1. 通用口径

阅读、处理、外部提醒分别定义。班级公共内容可供有资格的本班家庭阅读，不代表所有人都需完成；定向任务仅向目标家庭及有权管理者开放。撤销/换人告知使用独立最小事件，不因原任务取消或完成而被催办条件误拦；家庭关联失效仍撤销访问。

普通确认只表示收到、准备、报名意向等事务状态。正式监护人授权走学校现有渠道，另由有 consent.record 权限的管理者记录 PENDING / VERIFIED / REVOKED、核验人与说明版本；参加报名不能自动转成授权已取得。

## 2. 原生事务回填

- 字段限单选、整数数量、选项确认；预设参加/不参加、材料份数、已领取等，不做开放投诉或敏感个案表单。
- 同一孩子/表单/轮次一个当前回答，截止前可修改并保存版本；不同孩子独立，任何有效亲属代表该孩子操作的来源留痕。
- 不参加也算完成答复，不继续催“请填写”；报名意向、名额确认、正式授权分别展示。
- 管理员代登记记录真实操作者和来源，不伪装亲属亲自提交。返回待补充时注明理由，恢复未来允许的提醒点。
- 原生或腾讯文档为表单的唯一当前采集来源，只有有权管理者可配置或切换。已有答复后切换须生成新修订、核对旧答复迁移清单，保留来源和历史；不能双边同时写入并重复计数。

## 3. 志愿者与代报名

### 3.1 参与人与填写人

实际参与人保存稳定 participant_id、展示姓名/称谓、可空的小程序账号、可用岗位；填写人保存 submitter_user_id、有效孩子关联及代表的学生范围。实际志愿者可以没有账户或没有订阅。代填人必须是有正常账号及有效孩子关联的家长；其无微信订阅时站内报名仍有效，外发显示阻断。由孩子有效关联家长填写前确认已与参与人沟通并获同意，不要求志愿者另行注册。

一个家长有多个孩子时可选多个关联学生，但同一实际成人在同一岗位/时段只占一个名额；同一家庭两名不同成人可分别报名。先从本家庭已有参与人选择，再新增，不能用姓名相同自动合并。跨家庭疑似重复由管理员核验，合并/释放名额保留历史，不收集无关证件。

成人群组按 participant_id 维护，发送时解析到有权代填联系人；不向全体亲属发送“你已报名”。代填人失去关联后，报名保留待确认接收人，停止向旧人发送；新有权关联家长或管理员经核验接管，不能静默把联系方式交给无关家庭。

### 3.2 报名模式与状态

| 模式 | 提交与名额规则 | 通知与跟进 |
|---|---|---|
| 小程序代填 | 服务端按岗位/时段容量、参与人唯一性事务确认；满额进入候补 | 向有效代填人站内通知，微信仅有订阅条件时发送；请代填人转告实际参与人 |
| 腾讯文档填写 | 家长可打开/复制管理员配置的真实文档；回小程序自报仅是 REVIEW_PENDING（外部自报来源） | 管理员人工核验、匹配稳定参与人、检查名额后确认；不承诺外部表格实时限额或自动同步 |

原生创建直接进入 CONFIRMED（有名额）或 WAITLISTED（满额）；WAITLISTED → OFFERED（候补名额待确认）→ CONFIRMED。用户退出为 WITHDRAWN，活动取消为 CANCELLED。替补邀请有截止并预留容量，待确认名额不计入已确认人数，过期释放名额、记 OFFER_EXPIRED 并邀请下一个候补，不能当作本人主动退出；去重键为 activity_id + slot_id + participant_id，时段属于 slot_id。重复提交幂等，不能占双份名额。报名截止后的退出由管理员处理并留原因，不能简单删除历史。

外部自报统一为 REVIEW_PENDING（来源 source=EXTERNAL_SELF_REPORTED）→ CONFIRMED / WAITLISTED / NEEDS_INFO；NEEDS_INFO 补充后回 REVIEW_PENDING。自报不增加已确认人数，待核验不反复催家长填写；管理员核验后通知结果。名单、联系方式不作为全班公开内容，不进入 AI。

## 4. 活动统一入口

活动包含名称、日期地点、负责人、当前版本、状态和学生对象；关联报名表、志愿岗位、通知/准备待办、日程、正式授权核验状态、物资清单和费用项目。修改活动说明不自动覆盖老师发布的上级任务，仍按内容权限处理。

状态：DRAFT → OPEN → FINISHED / CANCELLED → ARCHIVED。取消先预览关联影响：报名关闭、未来日程取消、准备待办撤销、原/新家庭最小告知、费用待处置清单（RECONCILING + cancellation_requested，不自动退款或直接结项）。操作者必须有权处理所有必要关联项；权限不足时生成待有权者确认的方案，不允许只取消半边后声称整体完成。

整个取消修订生效后统一阻止继续执行，分批生成告知及派生记录。已收款、退款、支出及原回执保留；“活动已取消”“费用待核对/退款处置”“已实际退款”是三个不同事实。

## 5. 通知偏好与催款

按[需求 FR-MSG](requirements.md)集中控制总量。默认同接收人每日外发最多四次，普通初发/周期/催款合计最多两次，必要变更告知另最多两次；同一任务/轮次普通外发及催款子类各最多两次。间隔至少两小时，22:00—08:00 免打扰。手动、自动、摘要、跨班与重试共享计数，UNKNOWN 保守占额。

家庭主要接收人只改变外发选择，不改变其他亲属站内资格；未指定时沿用所有有效关联亲属。逐亲属确认各自提醒，志愿报名仅向代填责任人提醒。

每条催款固定提示：“款项同步可能有延迟，如果已交款请忽略。”有权管理者明确启用后才产生催款；已核实到账以最新账本立即停催，自报已交只暂停并等待管理员同步，不能增加实收。未缴差额、减免、退款调整按当前分摊计算，不按旧公示猜测。

管理端有未核对、未复核、待公示、微信无法提醒、无有效关联家长列表。原型已模拟每日两次额度和两小时间隔；真实时间、跨班并发和订阅必须在服务端验收。

## 6. 负责人维护与换届交接

### 6.1 日常维护

任务、知识、活动和费用项目均有 owner_id。管理者可按权限重新指派维护人、调整维护截止、检查知识有效期及替代来源。维护人不是原作者或原发布者；交接不能使家委会直接改写老师原文。

交接工作台显示：未完成/逾期待办、尚未核验表单、知识待维护/将过期、活动与志愿岗位、日程模板、材料保管、未核对款项、退款/垫付、账本及公示版本、实际资金差异、待撤销角色/委托。

### 6.2 生效流程

1. 有权管理者建立交接草稿，列明每项对象版本、旧/新维护人、生效时间、拟授予和撤销的具体权限。
2. 原负责人或指定管理者盘点；新负责人逐项确认接收，未完成项标记“继续跟进”并附负责人、截止，未核对资金如实保留差异。
3. 新权限必须经有权角色审批；接收清单不自动提权。财务经办与复核由不同账户承担；最高角色也不能自复核。
4. 有权管理者复核清单版本、接收状态和赋权/撤权上限，整体生效。若涉及其无权撤销的老师/系统管理员角色，交由系统管理员处理，不能用交接绕过角色管理权限。
5. 生效修订统一切换维护人与列明授权；旧授权立即失效，旧会话重新鉴权。物化记录异步展开不允许旧人继续凭过期授权操作。
6. 保留原作者、发布层级、回执、账本、票据、旧授权记录及交接审计；普通家长身份和孩子关联不因换届自动撤销。

状态：DRAFT → AWAITING_ACCEPTANCE → ACCEPTED → ACTIVE；生效前可转 CANCELLED，修改清单/接收人/授权后回到待接收并使旧确认失效。生效后更正另建交接，不覆盖历史。

缺少原负责人时系统管理员可组织盘点，记录实际盘点人和依据，不能伪造原负责人确认。日常监督可查看交接进度；私有财务材料仅指定职责人员可见。家庭公示展示当前负责人、账目版本、差异与更正历史，不展示管理权限明细和私人材料。

### 6.3 学期和退出

同一逻辑班级升年级保留班级 ID，发布新学期模板；转班和毕业归档在班关系，不复制旧亲属回执。家长退出后不得再读全班公示，但可通过受控申请、核验历史关系取得本家庭缴费资料，文件限时、脱敏并留审计。

## 7. 公共资料与物资

知识分类加入入学准备、家长会流程、阅读及学校确认的家庭教育资料，负责人维护有效期和来源版本。相同活动/事项的正式修订替代旧事实；不同活动不能仅因时间不同被判冲突。

轻量物资清单支持名称、数量、保管人、成人认领人、活动、领取/归还事件及关联支出。班内公开必要物资状态；联系方式和私人原因不公开。物资认领不自动采购或扣账，正式功能在 P6 实现并通过 B16，仍属已采纳范围。

## 8. 原型覆盖与正式验证

现有原型演示：发布类型及阅读/处理范围、原生答复、成人代报名与候补/外部核验、活动取消及正式授权分离、课程变动保留完成、最小变更告知、收款入账与公示分离、催款文案与上限、知识/活动/任务负责人交接和旧授权撤销、物资认领归还。

原型使用固定虚构班级、账户和账目，刷新重置；真正的微信授权、外部文档、云端事务、并发名额、真实账户权限和资金均未接入。正式验收按实施计划 A01—A30、B01—B20（B16 在 P6）、费用 F10/F11、日程 S01—S15 和 AI01—AI21 执行。原型的模式选择与时间推进是演示控制，不授予普通家长整项换源或绕过真实时间限制的生产权限。
