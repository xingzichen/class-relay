# 小程序方案文档

版本 0.6 · 2026-09-10 · 当前需求与设计基线；已交付本地 Web 原型，正式小程序及 CloudBase 后端尚未实施。

## 产品目标

老师和家委会发布一次，系统按学生范围通知有效关联亲属，跟踪答复与待办；活动汇总报名、志愿岗位、日程、物资和费用。日常维护及换届交接保留未完成事项、知识来源、活动负责人和完整账目，生效时撤销列明的旧管理授权。

产品服务可复用的班级事务，不承接投诉、冲突调解或敏感个案。AI 只依据授权的公共资料解释事项，不查询个人缴费、不代替正式监护人授权，也不执行审批或记账。

## 当前统一规则

1. 加入选择一项或多项身份；自选管理身份先申请后授权。系统管理员全局管理免逐班入班，老师/家委会按班级授权；家庭操作须有自己的有效孩子关联。委托不能绕过关联审批、角色管理或上级内容保护。
2. 通知按学生范围并集去重、发布冻结目标；有效亲属动态解析。公共阅读、需要处理的学生和外部接收人分别计算。普通通知默认无截止且无需确认；采集/待办须有截止。截止停止催办，默认允许补交。
3. 原生简单表单与腾讯文档是可选采集方式，每个表单只有一个当前有效来源。打开外部文档不算提交，外部自报与人工核验分开；已答复“不参加”也停止催填写。
4. 志愿者可以无账户或订阅，由有效关联家长代报名，或统一在腾讯文档填写。实际成人与代填人分开，同成人同岗位/时段不重复占位；外部自报不自动确认名额，候补提升需确认。
5. 默认同接收人跨班每日外发总计最多四次：普通初发/周期/催款合计两次，必要变更告知两次。催款另外受每日两次上限约束，手动/自动共享预算，间隔两小时，22:00—08:00 免打扰；微信还须满足实际订阅条件。
6. 每条催款含“款项同步可能有延迟，如果已交款请忽略。”已核实到账按最新账本停催，自报已交暂停待核对；公示是经审核发布的完整历史截止快照，不能用旧公示判定欠费。
7. 普通回执、报名意向、名额确认、正式授权分别记录。正式授权沿用学校渠道，有权管理者只记录必要核验状态。
8. 活动取消先核对全部关联影响与权限，统一生效；已收费用进入待核对/处置，不自动退款。移课保留原已完成准备，换人不复制旧人的回执，明确重新确认才开新轮次。
9. 交接含未完成事项、知识、活动、日程、财务差异和具体旧授权。接收不自动提权，生效统一切换维护人与列明授权，历史作者/回执/账目和正常家庭关系保留。
10. 知识按事项/活动身份与版本维护，不把不同活动时间判为事实冲突。轻量物资清单已采纳，正式交付排在 P6；家庭离班后只可申请本家庭历史资料。
