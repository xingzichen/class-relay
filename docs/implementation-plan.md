# 实施计划与验收

2026-09-09 · 当前仅交付文档与 Web 原型；以下是后续开发顺序，不代表正式代码已实现。

## 1. 分期

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 平台验证 | 主体/模板、CloudBase 环境/AppID/安全规则、混元模型/SDK/数据保留/Token 用量、真实文档跳转、已确认线下收款方式与逐学生公示；确定账务经办/复核安排 | 用真实后台、接口结果与真机记录可用能力，不用模拟结果替代 |
| P1 身份和家庭 | 登录、班级、四角色多选申请、管理员委托、学生/群组、亲属审批 | 自我提权、跨班访问、自审关联均被拒绝；多人多孩子正常 |
| P2 通知与回执 | 模板复用、课程/值日表及日期临时调整、定向任务发布、站内消息、订阅提醒、按学生/亲属完成、持续提醒 | 完成/撤销/截止停止催办，重启不刷屏，统计口径准确 |
| P3 采集与费用 | 腾讯文档填写、自报/核验、共享完成待办；费用事项、缴费核对、支出退款和结余公示 | 采集无假提交；费用全链路可对账和追溯 |
| P4 知识库和 AI | 按[腾讯云 AI 实施设计](ai-cloudbase-design.md)实现受控检索、混元调用、来源映射、权限过滤、结构校验、语气红线、预算与暂停开关 | 私人任务不进入模型、旧通知不继续误答、无依据/超时/预算耗尽有明确回退，AI01—AI18 及新增安全用例通过 |
| P5 单班试用 | 备份恢复、运营配置、真实家庭验收 | 核心用例通过，已知平台限制清晰展示 |

产品聚焦公共可复用事项；反馈受理、冲突调解和敏感个案不在实施范围。费用模块是用户要求的主方案范围，不作为长期搁置的可选插件。上述分期仅为实现先后；AI 与采集同样属于最终交付范围。

## 3. 端到端验收场景

以下均是待执行场景，不是本次文档编写已完成的测试。

| ID | 操作场景 | 预期 |
|---|---|---|
| A01 | 加入时选择老师＋普通家长 | 保留两个申请；老师未授权前无管理权，批准后本班权限生效 |
| A02 | 新用户勾选系统管理员或伪造角色字段 | 不会自助获得最高权限；首位管理员仅初始化绑定 |
| A03 | 老师将家长设为本班任务管理员 | 仅授予所选能力，不能管其他班、授予角色或审批孩子关联；撤销即时失效 |
| A04 | A 班老师进入 B 班任意对象 URL | 没有 B 班授权即拒绝；切换界面身份不能绕过 |
| A05 | 老师和家委会同时改同一学生，另有同名学生 | 检测编辑冲突，按 ID 区分同名，不覆盖错误孩子 |
| A06 | 妈妈、爸爸、奶奶申请同一孩子，妈妈还有另一孩子 | 支持多对多，称谓分别保存，未审批不收孩子通知 |
| A07 | 家委会为自己申请孩子并尝试自审；两人并发审批 | 自审被拒绝；并发只有一个有效终态，审批留痕 |
| A08 | 撤销关系后点击旧微信通知卡片 | 重新鉴权拒绝访问，取消未来提醒；历史外发不伪装为可撤回 |
| A09 | 女生＋自建群组＋学生多选有重叠 | 学生并集去重，未填写性别不混入女生；预览人数正确 |
| A10 | 发布后改群组、添加亲属或移出学生 | 群组不静默改变旧目标；新亲属加入开放事项；移出学生停止访问/催办 |
| A11 | 一个孩子有三位亲属，另一个没有亲属 | 三人建收件关系；无亲属孩子保留任务并标待补齐，不计通知成功 |
| A12 | 打开腾讯文档后直接返回；随后自报完成并被退回 | 打开不算提交；自报注明来源，退回恢复未完成；同源待办联动且不重复催 |
| A13 | 默认学生模式妈妈点完成；切到逐亲属模式重复测试 | 默认停止该孩子所有亲属催办；逐亲属只完成妈妈实例 |
| A14 | 一个家长两个目标孩子，仅完成其中一个 | 另一孩子仍待办；同一时点外发可合并，完成实例不合并 |
| A15 | 截止前计划重合、夜间、超过日上限 | 合并、顺延或跳过符合策略，不在截止后补发旧催办 |
| A16 | 取消/修订截止/重新确认与发送并发 | 旧计划失效，重新确认新轮次，旧回执保留；详情显示最新状态 |
| A17 | 明确失败、发送超时、发送后云函数超时/实例回收、定时重复触发 | 退避有上限；未知结果不盲目重发；队列可恢复且无集中补发 |
| A18 | 家委会解释与老师原通知矛盾、老师随后修订 | 不以权限等级猜事实；来源矛盾时暂不下结论且无反馈工单，修订后原文/索引/引用同步更新 |
| A19 | 普通家长问另一孩子定向通知并注入越权指令 | 检索前过滤，模型与来源下载均不能得到他人数据 |
| A20 | 模型不可用或知识无答案 | 原文和任务仍可使用，无依据明确说明，不自行审批/发布/完成 |
| A21 | 真机跨运营商访问和新环境恢复备份 | 云函数调用、云存储、微信云调用实际可用；回档集合/文件清单/权限/回执/账本相符后再启外发 |
| A22 | 同一孩子两位亲属分别声明已缴，重复上传凭证 | 不因声明增加实收；核对真实交易和分配，避免重复入账 |
| A23 | 40 人×50 元，收齐 2,000 元，打扫 600 元、布置 300 元、退款 100 元 | 账面余额 1,000 元；同时显示退款归属和调整后家庭缴费状态 |
| A24 | 已入账支出金额记错、家委会尝试直接覆盖或自复核 | 禁止覆盖和自复核；冲正/重记形成完整链路，公示生成新版本 |
| A25 | 家长访问费用页与凭证，跨班或猜原图 URL | 展示本班公示的所有孩子缴费状态与金额，自家缴费可查业务明细；跨班拒绝，原凭证受控 |
| A26 | 实际账户余额与账本不符、费用项目结项仍有结余 | 显示差异和原因，不虚构已对账；结余处置记退款/结转及审核记录 |

追加云开发验收：

- A27：客户端直连核心集合、跨路径上传、凭 fileID 读他人原始凭证均被拒绝；临时链接有效期和权限撤销边界可说明。
- A28：普通客户端不能调用内部调度/公示处理函数；定时函数不能复用上次家长的微信身份。
- A29：超过单事务容量的通知分批展开，中断重试无重复实例；取消后旧批次不继续外发。
- A30：财务入账后公示异步生成期间只显示完整旧版本与截止时间；新快照切换后所有金额来自同一修订。

AI 上线还必须通过[AI01—AI18 语气与边界用例](ai-response-policy.md)，日程上线通过[S01—S12](schedules.md)。

未来若启用小程序支付，追加测试：伪造客户端成功不入账、回调签名/商户/AppID/金额不符拒绝、重复回调只入账一次、查单补偿不重复入账、退款失败不扣余额、重启后支付/退款状态一致。
