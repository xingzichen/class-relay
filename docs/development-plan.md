## 2. 开发和测试的统一完成标准

### 2.1 每个开发包必须完成

1. 阅读依据及前置任务证据，先定义输入/输出、权限、状态、不变式和事务边界；模型中没有的列表/撤销/建议/审核动作，补最小契约与模型说明，不另开自建 HTTP 服务。
2. **先写单元用例并验证它能因缺失/错误行为失败，再实现，通过后重构。** 新增规则至少覆盖正常、边界和拒绝路径；持久写入增加重复请求、版本冲突和失败后状态；涉及时间用固定 Clock，涉及金额用整数分。
3. 单元测试调用实际领域函数/服务，替换数据库、时钟、微信、模型等边界；禁止用“测试中重新写一遍算法”替代测试生产代码，不只校验 mock 被调用或页面快照。
4. 真实云端事务、索引、安全规则、存储、定时和微信/模型均另做集成验证；并发测试使用并行请求/受控屏障，不靠 sleep 碰概率。前端测试覆盖状态转换、输入校验、失败恢复，真机检查实际交互。
5. 执行本任务单测及受影响依赖回归、类型/静态/构建检查；补证据并逐条对照验收。发现缺陷先加可复现单元回归；严禁关闭断言、增加无依据重试、排除业务文件来获得绿灯。
6. 更新任务状态、实际改动范围、剩余限制；本地通过但云验证未执行时保留“环境待验证”。接口返回成功、截图看起来正确或部署成功均不能代替验收。

### 2.2 工具与命令约定（P0 创建后才可运行）

首选沿用 TypeScript，并在 P0-01 固定单元测试运行器。可采用 TypeScript 编译后执行 Node 内置 `node:test`；若已有合适运行器就复用并记录版本。P0-01 已建立以下 npm 脚本；前三类离线检查可执行，集成/e2e/AI 总入口仍明确返回未配置。P0 管理侧云探针另用 `npm run test:cloud:p0`，不等同于完整集成验收：

```sh
npm ci
npm run lint
npm run typecheck
npm run build
npm run test:unit
npm run check
# 仅在显式配置的授权开发/隔离环境执行：
npm run test:integration
npm run test:e2e
npm run test:ai-eval
```

`check` 聚合 lint、typecheck、build、全部离线单测；网络集成、真机、真实 AI 不自动混入普通本地检查。P0-01 创建基本脚本，P0-02 建立测试任务映射；后续模块填充集成/e2e/AI脚本。无用例、环境缺失或未实现的命令应明确报未配置/失败，不能空返回成功，也不能把 skip 算通过。

覆盖率作为发现遗漏的辅助证据：每个新增业务规则、拒绝分支和不变式须有明确用例；P0 固定运行器后记录语句/分支覆盖基线，此后关键业务覆盖不得无解释下降。不能用行覆盖率代替并发、权限、账本、消息未知结果或语义评测。

建议路径：领域单测 `tests/unit/<domain>/`；云端集成 `tests/integration/<domain>/`；小程序/流程测试 `tests/e2e/`；AI 固定集 `tests/ai/`。P0-02 建立“任务编号 → 测试文件/用例”的索引，具体可执行命令写在验证记录中；本文不虚构尚不存在的命令参数或测试文件。

### 2.3 验证记录模板

每包交付 `tests/verification/<任务编号>.md`（目录由 P0 创建），内容如下；真实秘密/家庭资料另受控保存，Git 只放脱敏定位。

```text
任务：P?-?? / 标题；状态；执行者；日期；提交或构建标识
依据：需求/专题版本；前置任务状态；接口/数据变更
本地：实际命令、环境版本、通过/失败/跳过数量、规则覆盖及结果
云端：EnvId 的受控标识、SDK/运行时、测试账号角色、请求 ID、测试数据范围
验收：A/B/S/F/AI 编号；步骤；预期；实际；脱敏证据位置
故障与并发：注入点、并发数、最终不变式核对（按任务适用）
页面/真机：设备/版本、步骤、观察（无页面任务填不适用及理由）
结论：已验收/待环境验证/阻塞；缺项、责任人、下一动作
```

### 2.4 全程固定的业务边界

- 原生微信小程序 + TypeScript；后端全部 CloudBase 文档数据库/云函数/存储/定时器/混元。保留 Web 原型和备选分支，不迁回 OCR 群监听、NAS、SQL 或自建 API。
- 可信微信身份、每请求鉴权、财务显式职责/不得自复核、孩子关联不得自审；事务采用有界文档 ID 操作，外部调用不放事务回调。
- 消息按上海日期跨班统一：总4、普通2、变更2、催款2，最小两小时，22:00—08:00 免打扰；UNKNOWN 占额。站内消息与微信接受、已读、完成各自记录。
- 费用仅登记线下真实款项；申报不入账，入账与公示发布分开；公示班内逐学生，私有凭证不外泄。催款固定包含“款项同步可能有延迟，如果已交款请忽略。”
- 外部打开不算提交；参与人/代填人、普通回执/名额/正式授权分别记录；活动取消不自动退款。
- AI 不查询个人缴费/名册，不建投诉/敏感个案工单，不代转达或执行写操作。原文可见不等于可进入 AI。
- P6 物资属必交付；支付接入、自动抓取/同步腾讯文档、学生批量导入、自动值日轮换、向量增强、完整库存不是本轮追加工作，除非后续另有需求。

下列“需求主题”用于定位模块，不表示单包独自完成整组 FR；精确范围以该包交付/单测/验收及第 4 节映射为准。A/B 场景见原实施计划；S 见日程，F10/F11 见费用，AI 见回复规范。同一验收可以由多个包逐步覆盖，整条通过仍需阶段联合验证。
