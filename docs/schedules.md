# 课程表、值日表与临时调整

版本 0.3 · 2026-09-08。用户已要求课程表、值日表、老师串课及值日调整。以下周期、权限和通知细节为可调整的实施默认值，全部使用腾讯云开发。

## 1. 基础安排（FR-SCH-01 / FR-DUTY-01）

课程表按班级、学期维护，字段包括星期、节次、开始/结束时间、学科、任课老师、地点和生效日期。首版支持每周重复；可选择单双周，按班级明确的学期起始周计算，不使用日历 ISO 周号代替教学周。

值日表包含班级、星期或具体日期、值日时段/任务、目标学生或学生群组、负责人说明和生效范围。首版支持固定周表及按日期安排；自动轮换属于后续便利能力，不自动推断轮换顺序。

三者分开存储：可复用基础模板、指定日期的有效安排、临时调整记录。模板修订需要明确生效日期，不追溯修改已过去的上课/值日记录。

## 2. 查看（FR-SCH-02 / FR-DUTY-02）

小程序提供今日/本周视图与日期切换，展示当前有效课程、值日和临时调整标记。家长可筛选“与我的孩子有关”，查看值日时段和准备要求。

课程表和逐学生值日名单面向本班正常入班且关联在班孩子的家长、本班已授权管理身份展示，不向其他班或未审批访客开放。此名单是明确的日常安排公示，不提供后台学生管理名册或亲属联系方式。

AI 可说明有权查看的公共课程安排、物品要求、值日规则和操作方法；具体学生值日名单及完成记录由确定性页面展示，不由 AI 推断或评价个人表现。

## 3. 临时串课、代课、停课与补课（FR-SCH-03）

- 串课：选择具体日期/节次 A 与 B，预览原安排及交换后的学科、老师、时间、地点。
- 代课：保留日期/节次，修改当次任课老师，学科变更需明确指定；不等同于调换两节课。
- 改时间/地点、停课和补课：独立调整类型，填写受影响日期和说明，不能用删除原记录隐藏变化。
- 默认调整仅针对选定日期；要改长期周表需使用“修改基础表”并选择新的生效日期。
- 校验同班时间重叠、目标节次存在性、同一教师在系统已登记班级中的重复占用。无法掌握全校课表时不能承诺无全校冲突，发布预览注明校验覆盖范围。

系统管理员或对所有涉及班级有课程维护权的老师可发布调整。跨班串课只有在操作者对双方均有权限且校验通过时才整体生效；不允许单边提交。家委会默认可查看，课程编辑可由系统管理员/老师显式委托。

## 4. 临时值日调整（FR-DUTY-03）

系统管理员、所属班级老师、家委会委员共同维护值日表。支持换人、换组、换日期、换时段、增加/取消一次值日，发布前显示调整前后对象及提醒范围。

值日调整默认仅作用指定日期，不修改基础轮值。以新旧学生集合的并集计算变更通知收件人：被移出的家庭也需知道无需再按旧安排执行。理由只填写必要的公共安排说明，不要求输入疾病、家庭困难等私人原因。

学生离班后不能生成未来新值日实例；历史保留。需要补人时由管理者明确选择，系统不按家长活跃度或孩子表现自动安排。

## 5. 例外优先级和日历（FR-SCH-04）

按“学期基础版本 → 教学日历 → 日期有效调整”生成当天安排。节假日/停课日默认不生成课程或值日，可通过明确的补课/补值日例外重新建立一次安排。

同一日期和节次存在未撤销调整时，新改动需基于当前有效版本预览并提交，不能依赖时间最后写入随意覆盖。并发修改返回版本变化提示；撤销当前调整生成新修订，恢复当日当前应有安排，不删除变更历史。

日期使用 Asia/Shanghai。跨日期串课、单双周、学期切换及教学日历调整都以具体日期实例校验，周表视图对临时变化标记清楚。

## 6. 通知、待办和准备清单联动（FR-SCH-05 / FR-DUTY-04）

- 课程变更默认通知受影响班级学生的有效亲属；同一亲属多个孩子去重外发，详情列出其相关变化。
- 值日变更通知旧/新对象并集，通知正文中仅给当前家庭必要信息，不能把私人原因带进卡片。
- 准备事项可关联当次课程/值日，如“周三美术课带彩纸”。日期变化后其未完成待办截止和提醒随有效安排重算，保留调整记录。
- 被取消/替换的旧实例立即失效，停止旧计划；新实例按新日期生成。不把旧完成回执直接复制到新要求。
- 仅改地点等不改变完成要求时，保留原完成回执；需要重新准备/确认时，管理者显式选择新完成轮次并说明公共原因。
- 普通课表/值日查看不要求点击完成；需要家长准备/确认时才关联待办，按学生默认任一亲属确认；没有必要时不每天推送整张表。
- 所有外发仍受微信订阅条件、免打扰与限频约束。站内日程更新成功不意味着微信提醒保证送达。

准备清单跟随关联的课程事件 ID，而不是只跟随某个固定节次文本。例如美术课从周三调到周四，与该次美术课关联的彩纸准备也随其移动。

## 7. 模板复用（FR-SCH-06）

支持复制上学期课程/值日模板，生成新草稿后重新核对老师、当前学生/群组、学期起止和节次。复制不携带旧亲属、历史完成、临时调整或敏感原因；发布前预览新范围。

通用任务模板与日程模板只保存稳定结构、说明和相对时间，实例包含真实日期/对象。AI 不自动批准或发布串课、值日调整。

## 8. 云开发实现

| 集合 | 主要字段 |
|---|---|
| school_terms / teaching_calendar | class_id, start/end, teaching_week_anchor, holiday_dates, exceptional_days, version |
| course_templates / duty_templates | class_id, term_id, slots, recurrence, valid_from/to, version, status |
| schedule_changes | type, affected_dates, before_refs, after_chunks, source_versions, public_reason, publisher, status, revision |
| schedule_instances | stable_event_id, class_id, date, slot/time, course_or_duty, target_snapshot, template_version, change_revision, status |
| schedule_links | event_id, task_id, preparation_rule, follow_event_time, completion_round |
| schedule_outbox | change_id, revision, audience_snapshot, cursor, state |

`schedules` 云函数 action 包括 `saveTemplate`、`publishTemplate`、`getDay`、`getWeek`、`previewChange`、`publishChange`、`cancelChange`。所有命令检查班级、课程/值日管理权限、来源版本和受影响范围。

变更的全部 after 状态先准备并校验，manifest READY 后用小事务使整个修订生效并写 outbox；串课两侧引用同一发布修订，读取接口必须采用同一修订视图。派生日程与通知可异步分批物化，准备完成前不展示一侧新一侧旧。

有效日程读取不能只看未更新的物化表：物化版本落后时从已发布基础/调整清单计算当前视图，或提示正在更新，不能回传过期安排。提醒发送前重新校验有效日程修订。定时触发器只生成有限未来窗口内的实例，窗口初定两周并可配置，不能一次展开无限学期。

## 9. 验收

| ID | 场景 | 预期 |
|---|---|---|
| S01 | 发布每周课程和值日表 | 本班家长看到有效安排，其他班拒绝 |
| S02 | 交换周三两节课 | 两侧同时生效，下周基础课表不变 |
| S03 | 周三美术课换到周四，绑定彩纸准备 | 课程与准备截止同步移动，旧提醒失效 |
| S04 | 值日从学生 A 换为 B | A/B 家庭均收到变更站内通知，B 承担新待办，A 停止旧催办 |
| S05 | 代课但不换学科 | 只变当次老师，不误改长期课表 |
| S06 | 两位管理者同时调同一节课 | 后提交者看到版本冲突，不能覆盖另一人的修改 |
| S07 | 跨班串课只有一个班权限 | 整体拒绝，不产生单侧安排 |
| S08 | 节假日、明确补课、单双周交界 | 按班级教学日历与起始周正确生成 |
| S09 | 撤销临时调整 | 新修订恢复当前应有安排，历史可查，提醒重算 |
| S10 | 调整前待办已完成，新要求需重新准备 | 只有显式重新确认才新建轮次，旧回执不丢失 |
| S11 | 复制旧学期模板 | 不复制旧孩子关联、回执或临时调整，要求重新核对 |
| S12 | 变更发布后函数超时/重试、微信订阅不足 | 当前日程一致，分批幂等恢复，站内有效且微信阻断如实展示 |
