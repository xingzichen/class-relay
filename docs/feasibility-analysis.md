# 可行性与上线验证

版本 0.2 · 2026-09-08。本文区分产品设计、现有资源和需要实测的外部能力；不把链接存在视为接入成功。

## 1. 结论

身份、亲属审批、学生范围、任务回执、费用账目公示和知识库可以作为独立业务内核实现。最先验证的外部依赖是微信订阅消息、腾讯文档实际跳转、域名/主体要求和 NAS 面向家长网络的可达性。用户已选择线下/微信转账收款，第一版无微信支付接入依赖。

“截止前持续提醒”可以在业务计划中持续调度，但实际微信外发受平台授权和模板条件约束。平台不具备重复推送条件时，站内待办仍有效，不能将此降级描述为已经满足无限微信推送。

## 2. 微信订阅消息：首个验证门槛

候选方案使用一次性或长期订阅消息；长期能力不能仅凭业务属于教育就假定开通。上线前必须保存以下证据：

| 验证 | 通过证据 | 不通过时 |
|---|---|---|
| 主体和类目 | 实际小程序后台主体、认证状态、可用类目 | 调整主体/类目或功能范围，不借用不相关模板 |
| 消息模板 | 匹配通知/任务的实际模板 ID、字段、类型、规则 | 不支持的提醒仅站内展示，标出功能缺口 |
| 用户订阅 | 真机主动订阅、拒绝、撤销后的表现 | 不阻止业务使用，提示无法微信提醒 |
| 重复通知 | 同一亲属多次服务事件的真实发送及返回值 | 没有长期或剩余授权时不能承诺持续外发 |
| 状态语义 | 接口成功、详情打开、亲属完成分别记录 | 禁止用发送成功模拟已读或完成 |

## 3. 腾讯文档采集

“腾讯云文档”暂按腾讯文档/收集表理解；必须拿一个真实测试链接和目标小程序主体验证。

1. 验证是否存在官方支持的小程序跳转参数；不猜 AppID 或页面路径。
2. 若考虑 web-view，验证主体资格、业务域名配置、外部域名配合、登录和返回行为。服务器合法域名与 web-view 业务域名不是同一个配置。
3. 若无法直达，验证复制链接/指引的真实流程，明确交互成本，不把死链接算作采集功能交付。
4. 首版亲属自报加人工核验可独立实现；外部提交自动同步需要单独验证 API、授权和身份映射。

2026-09-08 腾讯文档开放平台入口可以访问，但未读到具体接口能力；微信 web-view 官方页面读取失败。未确认目标文档能否内嵌、跳转或返回提交回调。

- [腾讯文档开放平台](https://docs.qq.com/open/document/)

## 4. NAS 与 giraffee.top

用户已确认拥有 NAS、自有域名 `giraffee.top`，且已通过 cloudflared 打通。尚未确认 NAS 型号/架构、资源、域名 ICP 备案状态、隧道访问速度及小程序后台是否接受域名。

Cloudflare Tunnel 通过出站连接发布本地服务，不需要 NAS 具备公网可路由 IP；这是隧道连接能力，不代表微信审核或业务可靠性已通过。[Cloudflare 官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)

| 验证项 | 操作与结果要求 |
|---|---|
| 域名备案 | 工信部官方查询 giraffee.top，保存实际结果；此前公开搜索无记录不等于未备案 |
| 小程序备案/主体 | 单独在微信后台确认；域名备案不自动完成小程序自身备案 |
| 合法域名与 HTTPS | 实际配置拟用 API 域名，真机请求和附件上传下载成功 |
| NAS 运行资源 | 确认 CPU 架构、容器能力、内存、磁盘，先用模拟数据部署 |
| 实际访问 | 移动/联通/电信、Wi-Fi/蜂窝网络和晚高峰实测，不只测开发者本机 |
| 入站访问控制 | API 不能被浏览器挑战页或 Access 登录页代替，应用鉴权仍有效 |
| 微信 API 出站 | 登录交换、凭据获取、订阅发送在 NAS 正常；若有 IP 白名单要求另测 |
| 断网/重启 | 业务数据恢复、队列恢复无集中补发、结果未知不盲目重发 |
| 备份恢复 | 新环境恢复任务、回执、权限和账本，对账相符后恢复发送 |

普通 Cloudflare 网络不能直接等同于其中国大陆专用网络，后者是独立方案；家长网络表现必须实测。[Cloudflare 中国网络说明](https://developers.cloudflare.com/china-network/)

- [工信部备案查询](https://beian.miit.gov.cn/)
- [微信网络能力核验入口](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

## 5. 费用收取与公示

费用模块详见[费用规范](finance.md)。已确认第一版采用线下/微信转账收款，小程序核对登记；逐学生缴费状态和金额向班内公示，并展示支出、退款与结余。

未来若扩展小程序内微信支付，必须验证认证小程序、支持的商户主体、支付权限和 AppID 授权绑定。2026-09-08 查阅的微信支付官方文档明确列出以上接入准备；不能用个人微信收款码冒充小程序支付接口。[官方开发接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)

在线支付还需验证回调验签、金额/订单核对、幂等入账、主动查单、对账与退款结果，不使用客户端“支付成功”作为到账凭据。没有资质/商户配置时仍可做账目模块，但不能宣称已支持小程序内支付。

系统保存收费依据/用途、家长确认记录、代收负责人和公示资料；是否可以就某个学校事项实际收费，需要运营方依据当地学校规则确认，文档不将小程序内部审核等同于学校批准。本次不发起收费或交易。

## 6. 成本口径

已有 NAS 全天运行、现有域名和免费隧道资源可复用时，可减少另租云后端的基础费用。仍需计入小程序认证/年审（按主体后台为准）、域名续费、增量电费、备份、维护、可选 AI 调用和在线支付相关服务费用。

不按“已有 NAS”推导绝对零成本；也不为通过域名配置而先行购买不必要的云服务。若 NAS 网络验证失败，可迁移同一业务容器/数据库到合适的云环境，保留 NAS 备份。

## 7. 正式试用门槛

需有一个真实班级完成身份审批、亲属绑定、定向发布、消息授权、完成停止催办、知识引用和费用对账公示全流程。关键平台功能未通过时继续使用测试数据并清楚标记缺口；不让页面演示代替实际外部能力。
